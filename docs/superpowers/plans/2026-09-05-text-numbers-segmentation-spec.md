# 规格:让存成文本的数字进入分块

状态:规格待评审,未动代码。

## 缺口

工作簿路径(`.xlsx` / `.xls` / `.xlsm`)把行喂给 `_audit.py` 的 **`_fill_sheet_from_rows`**
——openpyxl 与 calamine 两条读法都走它——它用 `is_num` 判定一个格子进 `numeric` 还是
`_text`,而 `is_num` 只认 Python 的 `int`/`float`。于是单元格里存成文本的 `"21.5"` 对
**所有**检测器不可见(已核对:`_text` 只被 `sheet.cell()` 读作标签/表头,没有检测器扫它)。

**改动点是 `_fill_sheet_from_rows`,不是 `Sheet.from_rows`。** 后者只服务 CSV 与
PDF/DOCX 路径——也就是本来就正常的那两条。本规格第一版写成了 `Sheet.from_rows`,照那么改
对 .xlsx 毫无效果;`_sheet.py` 里那份实现与 `_fill_sheet_from_rows` 是手写重复的两份。

同一个仓库的另外两条路径不是这样:CSV 路径(`load_csv_rows`)和 PDF/DOCX 提取
(`_extract.py`)都把每个格子过一遍 `_coerce_cell`,因为那两条路上所有值本来就是字符串。
**同一份数据存成 .csv 能看见,存成 .xlsx 就看不见**——这是路径间的不对称,不是有意的设计选择。

## 语料实测

| | 值 |
|---|---|
| sheet 总数 | 6462 |
| 含"可解析为数值的文本格子"的 sheet | 206(3.2%) |
| 文本格子总数 / 其中可解析为数值 | 4,781,598 / 153,606(3.2%) |
| 转换后**块数**变化的 sheet | 74 |
| 转换后**块坐标**变化的 sheet | **109** |

74 是按 `len(blocks)` 比出来的,漏掉了 35 张块数不变、边界移动的 sheet(即上面第三类)。
**口径应为 109**,按块坐标逐块比对,否则会漏掉三分之一。

109 张里包含数张 `0 -> 100+ 块`,即整张表当前完全不可见。

**另有 44 张 sheet 超过 40 万格子,被本次测量跳过,而它们不该被跳过**:这 44 张含 662 万个
文本格子(比被测量的全部还多)、其中 13.7 万可解析为数值,与被测量的 15.4 万同一量级。
生产环境 `PAPERCONAN_MAX_CELLS` 默认一千万,**这些表实际会被扫**。已知其中一张的块数会从
854 变到 1902(+123%),远超上面 `0 -> 143` 的例子。测量必须覆盖它们,或明写为何不覆盖。

## 已核实的真实案例

一个已人工打开源数据确认的案例:某面板两行之间逐列差值恰为 +3.0(10/10 列,小数尾数逐位
保留)。当前该面板不进任何块。转换后进块 `(3, 11, 2, 13)`。

**但转换本身不足以让它被报出来**,这一点必须写在前面:该关系是行对关系,`detect_row_relations`
的 `_ROW_REL_MIN_COLS = 12` 要求至少 12 列,而该块是 11 列。**差一列。**

所以本规格只做第一段(让数据进块),不改任何门槛。第二段(11 vs 12)是独立的一件事,
证据在此记下,单独评估——把两件事塞进一个改动,就无法分辨哪一段带来了哪一部分效果。

## 该转什么

复用现有的 `_coerce_cell`,不新写解析器。它已经是保守的:不认千分位、不认百分号、
不认货币符号,空串转 None。CSV 与 PDF/DOCX 路径已经在用它,**用同一个函数是为了让三条
路径对同一份数据给出同一个 Sheet**,而不是为了省事。

## 必须带的保真闸:非有限值

`_coerce_cell` 用的是裸 `int()` / `float()`,它们接受的远不止十进制数字:`"NaN"`、
`"Infinity"`、`"-Infinity"`、`"1e999"` 全都会变成 float 的 nan/inf。

这已经是一个**现存的活 bug**,与本规格无关:CSV 路径里 `_coerce_cell` 先于
`Sheet.from_rows` 执行,`is_num(nan)` 为假于是走 `_text` 分支,但**存进去的是已经转换过的
float**,不是原字符串。实测源文件里写文本 `NaN`,`cell()` 返回 float `nan`,违反 `_sheet.py`
自己声明的"`cell()` 原样返回源值",且 `json.dumps` 会吐出非标准的 `NaN` 字面量。

语料里有 635 个这种形状的文本格子(计算流水线常见的占位写法)。本规格若不带闸,会把这个
bug 的暴露面从 CSV 扩大到 478 万个 xlsx 格子。

**要求:转换后先判 `is_num(coerced)`,为假则保留原字符串。** 这是正确性要求,不是实现细节。
CSV/PDF/DOCX 路径上那个既有实例应当单独修,不依赖本规格是否落地。

## 不该转什么

- **不转日期/布尔**。`_is_num` 明确排除 bool;`_coerce_cell` 不碰 datetime 对象。
- **不做区域格式**。逗号小数点、千分位一律不认,与 `_coerce_cell` 现有承诺一致。
- **不改 `_is_num` 本身**。它被 `_audit.is_num` 镜像,改它会波及远超本规格的范围。
  转换发生在构造 `Sheet` 之前(输入行上),不在判定谓词里。

## 风险:分块会变多,包括不想要的方向

74 张 sheet 的分块结果会变,方向不全是好的:`0 -> 143 块` 既可能是"一张原本不可见的表
终于可见",也可能是"一张稀疏表被切成 143 个碎片"。**这两者必须分开量**,不能只报总数。

**还有第三类,第一版规格完全没提到:表头/坐标轴行被吸进数据块。** 一行文本型数字的坐标轴
标签(如 `'0','4','8','12'`)转换后成了数值,块的起始行前移一行把它吞掉,`header_for` 于是
返回空标签——证据里的坐标轴名就此丢失。这类降级是温和的(代码本就有无表头的回退路径),
但它影响约三分之一的受影响 sheet,必须单独计数,不能混进"新可见"里。

已知的碎片化上限:语料中现有最坏的 sheet 已经是 7,580 块 / 7,580 个不同行范围
(`_merge_panels` 按 `(scope, file, sheet, block_rows)` 合并,行范围各不相同则一个都合不掉)。
本改动会不会制造新的这一类,必须在验收里明确回答。

## 验收(每条都要有跑出来的数)

1. 那个已核实案例的面板进块,块坐标为 `(3, 11, 2, 13)`。**不承诺它被报出来**——`_ROW_REL_MIN_COLS`
   是另一件事。
2. **109** 张变化的 sheet(按块坐标比对,不是按块数)逐张分类:新可见 / 碎片化 /
   表头被吸收 / 其他。碎片化的那些给出块数与不同行范围数。超过 40 万格子的 44 张一并测。
3. **按 agent 读到的那一层量代价**(AGENTS.md 第一条):在受影响的论文上比较 `overview` 首屏,
   看已有的真信号是否被挤下去、排名是否变化。检测器发射量的变化不是代价。
   **代价非零且因论文而异**,已知:一篇小论文上原本排第 1 的 high 信号被两条新增的 high
   挤到第 5(该篇总位置数 7,未过 20 的页界,所以没被挤下页;位置数超过 20 的论文上同一机制
   就会挤下页)。一篇密集论文上首屏 20 行逐字节不变,新信号落在第 22、28 位——**代价和收益
   都没进首屏**。所以这一项要在语料规模上跑完再合,不能拿两篇的样本下结论。
4. 全语料扫描耗时变化,以及 `PAPERCONAN_MAX_CELLS` 等上限是否被新可见的数据顶破。
5. 现有测试全绿**不够**——需要新增夹具。`test_streaming_matches_from_rows` 与
   `test_calamine_matches_openpyxl` 断言加载器输出等于 `Sheet.from_rows(未转换的原始行)`,
   这在夹具里没有数字形文本时才成立;改了 `_fill_sheet_from_rows` 而(按边界)不动
   `Sheet.from_rows` 之后,新夹具必须两边都转,否则这条不变式测试会变成空转。
   golden 输出若变化,逐条说明为什么该变。演示论文的两个 xlsx 无可解析文本格子,不受影响。

## 边界

- 不改任何检测器的门槛或容差。
- 不改 `find_numeric_blocks` 的切分逻辑本身——本规格只改喂给它的数据。
  稀疏表被切碎是一个独立的、已量到的问题(最坏 7,580 块),单独处理。
- 不碰跨块比较(见同目录 `2026-09-05-cross-block-comparison-spec.md`,已评审为不实施)。

# 实施后的验收测量(2026-09-06)

分支 `fix/coerce-text-numbers-in-workbooks`。改动点:`_fill_sheet_from_rows`(工作簿路径)
过 `_coerce_cell`,`Sheet.from_rows` 同步跟进(两份实现被 loader 对等性测试比对,不同步会
让那条不变式空转);`_coerce_cell` 加非有限值闸,顺带修掉 CSV 路径上那个既有的保真 bug。

## 通过的部分

1. **已核实案例进块**:块坐标 `(3, 11, 2, 13)`,与规格预期一致。
2. **全套测试**:2028 passed, 2 skipped, 0 failed。(`test_detection_recall_e2e.py` 的收集
   错误在 main 上同样存在,与本改动无关;用 `PYTHONPATH=.` 可绕过。)
3. **分类(按块坐标,含大表)**:6497 张里 112 张变化 —— 新可见 10、块数增加 42、
   块数减少 25、**仅边界移动 35**(按块数比会漏掉这 35 张,证实规格改正的口径是对的)。
4. **碎片化不产生 finding**:那张 49,316 行的基因组学表块数 854 -> 1902,但改前改后
   findings 都是 **0**。新增的块全部空转。

## 未通过的部分:一张仪器输出表挤掉了真信号

按 agent 读到的那一层测(AGENTS.md 第一条),三篇受影响论文:

| 论文 | 位置总数 | 首屏 |
|---|---|---|
| A | 5 -> 7 | 挤下 2 个 medium,新进来的是真信号(那个已核实的面板终于上榜) |
| B | 99 -> 103 | **逐行不变** |
| C | 67 -> **158** | **挤下 7 个,其中 4 个是 high** |

C 的首屏被一张新可见的表占据。打开看,那是**质谱鉴定清单**,不是图的源数据,其列之间
本就有确定的算术关系:

- `col[3] == col[4] in 11/11 rows` —— 实测质量与理论质量,本就该几乎相等
- `col[3] = 2 * col[2] + -2.015` —— 电荷 2+ 的质谱换算公式本身
- `col[9] = col[6] + 1` —— 两个常数列
- `col[8] has value 0.0 repeated 8/11` —— 漏切位点数的正常分布

**这不是可以放行的代价。** 4 个真 high 信号被一整页仪器输出的算术恒等式挤下首屏,而这些
恒等式对读者没有任何信息。

## 结论:改动本身正确,但需要一道闸才能合

转换是对的(数据本就该可见,碎片化不产生噪声,真信号确实上了榜)。缺的是**区分"图的源
数据"与"仪器/软件输出的清单"**的判据 —— 后者转换后新可见,且天然充满算术关系。

已知可用的线索,均未验证,按可疑程度排序:
- 表头字段名(`Mr(expt)` / `Mr(calc)` / `Score` / `Miss` 这类是软件输出的固定列名)
- 行数量级(2662 行的清单 vs 数行到数十行的图源数据)
- `_prefilter.py` 是否已有此类判据可复用(未查)

在有这道闸之前不合。下一步应先量:112 张变化的 sheet 里,有多少属于"仪器输出清单"这一类,
以及它们在首屏上挤掉了什么。
