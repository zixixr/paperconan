# 设计：短行复用检测器改用「偶然概率」判据，替换硬精度门槛

- 日期：2026-07-30
- 涉及：`detect_short_row_reuse`（`_audit.py`）及其精度判据 `_is_short_hp` / `_can_pin_a_ratio`
- 前情：#56 把「一个判据回答两个问题」拆成了两个，但两个都仍是**硬门槛**。本设计要换掉门槛本身。
- 承接原则：`2026-07-19-detector-hard-threshold-audit.md` 的既定判据——**用显著性过滤，不用硬样本量门槛**。

> ⚠️ 中立措辞红线：本检测器产出的是**统计信号 / 数据不一致 / 待作者澄清 / data inconsistency**，
> 不构成对任何人的指控。原始记录、图注、Methods、作者答复与期刊/机构复核才能定性。文档、代码、
> 变量名、报告文案一律遵守此红线。

---

## 1. 这个检测器在找什么

补充材料里，**B 行 = A 行 × 一个固定常数，逐格精确成立，连续若干列**。两组真正独立测出来的数据不会
这样。这是「一份数据被复制到另一处，并整体缩放」留下的指纹，也是本仓库目前最强的信号族之一。

因为面板往往很小（每个子图 1–4 行），匹配段只有 3–11 列，所以它必须能在**短段**上下结论——而短段
容易撞上巧合，于是需要一个门槛来决定「哪些格子够格参与比对」。

问题就出在这个门槛上。

---

## 2. 问题

### 2.1 现状：门槛数的是「每一格记了几位小数」

进入匹配的格子必须满足 `frac ≥ 3`（至少 3 位小数）。这是一个**逐格、绝对、与匹配长度无关**的判据。

### 2.2 症状一：接近四分之一的数据表完全不可见

对本地 212 份真实补充材料按 sheet 统计（只算含 ≥30 个非整数值的数值表）：

| 该表数值的中位小数位 | sheet 数 | 占比 | 本检测器 |
|---|---|---|---|
| 0–2 位 | **170** | **23.7%** | **完全看不见** |
| 3 位 | 80 | 11.1% | 可见 |
| 4 位 | 61 | 8.5% | 可见 |
| ≥5 位 | 407 | 56.7% | 可见 |

**近四分之一的数值表在这个检测器眼里是空白**，与表里有没有问题无关。

### 2.3 症状二：被挡掉的里面有证据非常硬的

合成例子（2 位小数，两个面板，B 组 = A 组 × 0.8409，**8 列全中**）：

```
          Rep1    Rep2    Rep3    Rep4    Rep5    Rep6    Rep7    Rep8
Vehicle  42.13   58.91   19.37   71.20   33.84   26.55   49.02   61.78
Treated  35.43   49.54   16.29   59.87   28.46   22.33   41.22   51.95
逐列比值 0.84097 0.84094 0.84099 0.84087 0.84102 0.84105 0.84088 0.84089
```

八列的比值一致到**万分之二**。当前输出：**什么都不报。**

对照：3 位小数、只连中 3 列的情况，工具会报。**后者的证据比前者弱得多。** 现在的门槛把这两件事的
强弱关系搞反了，因为它只看每格精度，不看连中了几列。

### 2.4 为什么硬门槛是错的工具——实测

40 张表 × 30 行 × 8 列、**全部互相独立**的随机数据，因此下表每一个数字都是纯误报。容差按「该精度下
一次真实的复制缩放重新取整后所需的容差」设定（比这更紧就会漏掉真的）：

| 数据形态 | 小数位 | 连中3列 | 连中4列 | 连中5列 | 连中6列 |
|---|---|---|---|---|---|
| 跨两个数量级（1–100） | 1 | 1 | 0 | 0 | 0 |
| 百分比（0–100） | 1 | 0 | 0 | 0 | 0 |
| 小量程读数（1–20） | 1 | 2 | 0 | 0 | 0 |
| **归一化值（集中在 1.0 附近）** | 1 | **1867** | 286 | 40 | 6 |
| 归一化值 | 2 | 33 | 1 | 0 | 0 |
| 归一化值 | 3 | 0 | 0 | 0 | 0 |
| **同一条平滑曲线上的行** | 1 | **16549** | 14487 | 10904 | 6381 |
| 同一条平滑曲线上的行 | 2 | 5180 | 1710 | 467 | 85 |
| 同一条平滑曲线上的行 | 3 | 76 | 4 | 1 | 0 |

三个读数：

1. **对大多数数据形态，1–2 位小数的固定比值本来就极罕见**（17400 对里 0–2 次）。现有门槛对它们过严。
2. **真正制造误报的是两种数据形态，不是「精度低」本身**：值域窄到挤在一起（归一化 / fold change），
   以及同一条平滑曲线上取的点（剂量反应——相邻行本来就近似成倍数，这是曲线的定义，不是异常）。
3. **压制误报最有效的变量是「连中几列」，不是「每格几位」**。看曲线那一行：2 位小数下，连中 3 列
   5180 次，连中 6 列只剩 85 次——指数级衰减。

### 2.5 结论

该判定的是**这件事偶然发生的概率**，而它由三件事共同决定：

- **值域有多宽**（相对于容差）——决定单列凑巧落进窗口的概率
- **记了几位小数**——决定容差必须放到多宽
- **连中了几列**——概率按列数指数衰减

现有门槛只取了第二项，还把它当成逐格的通过/否决，于是既漏掉长段中精度的强证据，又没能针对性地
压制真正的误报源。

## 3. 设计

两个必须一起做的改动。只做其一都会变差：只放宽容差会泛滥，只加显著性而不放宽容差则够不着 2 位小数。

### 3.1 改动一：容差跟随每格的量化误差

一次真实的复制缩放，写回表里时会按面板精度重新取整，比值因此被扰动。对一对格子 `(a, b)`，扰动上界：

```
δ = (q_a/2)/|a| + (q_b/2)/|b|        q = 10^(-该格记录的小数位)
```

匹配容差取 `τ = max(_SHORT_ROW_RTOL, 2δ)`（2 倍余量的理由与既有整行判据一致：run 内各格锚定的是
run 起点的比值，而报出的 k 是均值）。

用 §2.3 那个例子验一下：`a=42.13, b=35.43` → δ = 0.005/42.13 + 0.005/35.43 = 2.6e-4，
实测比值散布 2e-4 —— 模型与实测吻合。

**这一步单独做会让误报上升**，必须由改动二兜住。M1 里要把上升幅度量出来。

### 3.2 改动二：用「期望偶然次数」代替精度门槛

**零假设**：两行是同一张 sheet 的值分布里独立抽出来的。

**单列匹配概率**：run 锚定比值 `k` 后，第 i 列要求 `b_i` 落进宽度 `2τ·|k·a_i|` 的窗口。用**该 sheet
自己的经验分布**估计：

```
p_i = (该 sheet 中落在这个窗口内的值的个数) / (该 sheet 的值总数)
```

不假设任何分布形状；是确定性的（按行列序遍历，不用随机采样）。

**一条 run 的偶然概率**：run 的第一列用来定 `k`，不提供证据，所以

```
P = Π(i = 第2列 … 第L列) p_i
```

**多重检验修正**：一张 sheet 里被检验过的 (行对 × 起始列) 数目记为 `n_tests`，则

```
E = n_tests × P          # 期望偶然命中次数
```

**判据**：`E ≤ α` 才报（α 默认 0.01，env 可调）。`E` 一并写进 finding。

用 §2.3 的例子核算：b 的取值域约 20–60、格点 0.01 → 约 4000 个格点；窗口 ≈ 2×2.6e-4×35 ≈ 0.018，
约 2 个格点 → `p ≈ 5e-4`。8 列 → `P ≈ (5e-4)^7 ≈ 8e-24`。乘以 `n_tests`（这张表个位数）仍然极小，
**显著**。这正是现在完全看不见的那条。

反过来，2 位小数、只连中 3 列的情况：`P ≈ (5e-4)^2 = 2.5e-7`，一张 30 行 × 8 列的表
`n_tests ≈ 435×8 ≈ 3500` → `E ≈ 9e-4`，仍然显著。**这说明 α 不能只靠这一条兜底**——见 3.3。

### 3.3 显著性解决不了什么（必须说清楚）

上面的零假设是「两行相互独立」。**§2.4 里误报最凶的那两种形态恰恰违反这个前提**：

- **同一条平滑曲线上的行**：相邻行本来就是彼此的近似倍数。这不是小概率事件，而是数据的构造方式。
  任何建立在「独立」零假设上的概率模型都会把它算成极显著——**算得越准，报得越多**。
- **归一化数据**：值挤在 1.0 附近时，窗口会覆盖值池的很大一块，`p_i` 自然很大 → `E` 大 → 自动不显著。
  **这一种显著性能自己处理。**

所以曲线那一类**必须继续由结构性守卫处理**，即现有的 `_same_band`（同一连续数据 band 内的比值视为
曲线台阶）。显著性判据与它是**互补**关系，不是替代关系。

同理，量化网格（k/19 这类）由现有的 `_rare` 频率闸处理，等差/等比行由 `_vector_is_patterned` 处理。
本设计**不动这三个守卫**。

### 3.4 报出来

finding 里新增 `chance_expectation`（即 `E`）与 `run_length`、`tolerance_used`。读报告的人和判定的
agent 由此能分辨「8 列 2 位小数」和「3 列 5 位小数」哪个更硬——这是目前完全缺失的信息。

## 4. 风险与已知边界

| 风险 | 处置 |
|---|---|
| **这是本仓库最强信号族之一，任何改动都可能砍掉真实产出** | 每个里程碑都必须跑 212 份本地语料对比，且**逐文件**比对而非只看总数。C4 的教训：全量测试绿的改动砍掉了 61% 的真实产出。 |
| 曲线形态违反零假设 | 不靠显著性解决，保留 `_same_band`；M3 的验收里必须单独确认曲线语料没有上升。 |
| `p_i` 用整 sheet 值池估计，对多面板 sheet 偏粗 | 先按整 sheet 做，M2 里量一下按 block 估计是否更准；不确定就保留整 sheet（偏保守 = 少报）。 |
| 计算量：每条候选 run 都要算 `p_i` | 值池预排序 + 二分，单列 O(log n)。要落进现有 `_SHORT_ROW_BUDGET` 预算记账，超限如实记 coverage。 |
| 确定性 | 不使用随机采样；值池按 (行,列) 序构建。golden 测试守住。 |
| 2 位小数放开后，`identical` 臂也会被波及 | 本设计只动 ratio 臂的判据。identical 臂另议，M3 里量它的变化量。 |

**明确不做**：不动 `_same_band` / `_rare` / `_vector_is_patterned`；不动长段检测器
（`detect_scaled_row_reuse`、`detect_row_relations`）；不碰比例表爆发那个已知误报面
（见 `2026-07-19` 文档，已实测四种改法均否决）。

## 6. 这件事做成之后，什么变了

- **覆盖面**：23.7% 的数值表从「结构性盲区」变成「长段可查」。这是目前已知最大的一块系统性漏检。
- **判据**：从「每格几位小数」变成「这件事偶然发生的概率是多少」——可解释、可校准、可写进报告。
- **强弱关系摆正**：8 列 2 位小数会排在 3 列 5 位小数前面，而不是根本不出现。

**仍然不变的是红线**：报出来的是统计信号，不是结论。`E` 再小也只说明「偶然解释不了」，不说明
原因——复制、共享对照、派生列、单位换算都可能产生它。定性仍然要原始数据、图注、Methods 和作者答复。
