# 审计：所有 detector 的硬门槛 —— 样本量 floor vs 有效性门槛

- 日期：2026-07-19
- 缘起：`detect_block_value_duplication`（PR #39）确立的原则——**用显著性过滤，不用硬样本量门槛**。
  已知两个真实漏检因硬门槛而起：S4D（行比率被 `_ROW_REL_MIN_COLS=12` 挡）、3A（局部尾数复用被
  `_TAIL_CLUSTER_MIN_N=100` + 整-sheet 粒度挡）。
- 目的：把每个 detector 的硬门槛盘一遍，分类，定出该改哪些、保留哪些，再复测。

> ⚠️ 中立措辞红线：detector 产出的是**统计信号 / 数据不一致 / 待作者澄清**，不构成对任何人的指控。

---

## 分类框架（关键判据）

一个 floor 该不该改，取决于它守的是"数据够不够"还是"统计有没有意义"，而这又取决于**检验的类型**：

| 类 | 含义 | 处置 |
|---|---|---|
| **A. 重复/衝突/关系类的样本量 floor** | 检验的是**精确巧合**（重复值、相同列、行比率/偏移）。这类信号靠 **birthday 逻辑**——少数几个高精度精确巧合本身就极不可能，**不需要大 N**。此处的 N-floor 是**错的**，会误杀小样本/少量复制的真信号。 | ✅ **审查目标**：改成显著性（泊松 birthday，同 block_value_duplication），或降 floor + 交 prefilter。 |
| **B. 分布/频率检验的检定力 floor** | 检验的是**分布形状**（末位数均匀性、小数末两位频率、位分布 χ²）。这类**天然需要 N** 才有检定力；N 太小时检验本就无意义。 | 🔵 **保留**（可选：换成直接报 p 值的检验，让小 N 自然不显著，去掉突兀的硬 floor）。 |
| **C. 有效性门槛** | "统计到底成不成立"：birthday support（`N_eff≥K·m`）、反量化（full 分数须多样）、定义一条线/比率至少要 ≥3 点、共享分数至少要 ≥K 位小数才有意义。 | 🔵 **保留**。 |
| **D. 计算/内存预算上限** | `MAX_*`、O(n²) 检测器的行/列上限、evidence 截断。与信号无关，纯护栏。 | 🔵 **保留**（但 CLAUDE.md：截断要如实记 coverage，不静默）。 |

**一句话判据**：*这个检验能不能在小样本上给出可信信号？* 精确重复/巧合类 → 能（改）；分布/频率类 → 不能（留）。

## 复测计划（改前先立“会漏”的回归证据）

对每个 A 类目标，先写一个**当前会漏、改后应中**的最小固定用例（真实布局，不含 DOI/敏感信息），再动刀：

1. **`_ROW_REL_MIN_COLS=12` → S4D**：5 列 `行B = k·行A`（部分列比率，k 为非 `10^n` 常数）。
   断言当前 `[]`、目标命中。**合成数据**，不使用原始值。
2. **`_TAIL_CLUSTER_MIN_N=100` + 粒度 → 3A**：约 40 个值的局部尾数复用（若干高精度值各重复 3 次）。
   断言当前 sheet 级 `None`、目标 block/panel 级命中。**合成数据**，不使用原始值。
3. **`detect_dispersed_repeats` `min_n=30`**：一个 ~15 行、少量高精度精确重复的列。
4. **`detect_equal_pairs` `n=6`**：5 行完全相同的列对。

改造统一走 `_poisson_sf` + `_birthday_grid` 显著性核（已在库中）。每步保持全 golden 绿 + Monte-Carlo FP 复核。

## S4D 复测结论（2026-07-29）

动手前先实测，结论和上表原来的判断**不一致**，记录如下。

**1. 12 列门槛不是 S4D 的原因。** 3–11 列的部分比率早已由 `detect_short_row_reuse` 覆盖。
真正拦住的是它的每格精度闸 `_is_short_hp`。

**2. 那个精度闸把「精度」和「量级」混在一起。** 原判据是 `frac ≥ 3 且 sig ≥ 5`。同样记录到
3 位小数的两个数，`12.346` 过闸而 `7.891` 不过——差别只在于一个 ≥10 一个 <10。而 run 中间掉一格
就把 5 列劈成 2+2，双双低于 3 列下限，整条关系消失。合成语料实测（k=0.8409，5 列精确比率，两行
都按面板精度重新取整）：

| 数据 | sig figs | 结果 |
|---|---|---|
| 全部 ≥10，3 位小数 | `[5,5,5,5,5]` | 报出 |
| 其中一个 <10，3 位小数 | `[5,5,**4**,5,5]` | **漏掉** |

改法：闸门改数**记录小数位**（`_SHORT_ROW_MIN_FRAC_DIGITS=3`），与量级无关。原来那条「短低精度
行复用无意义」的有效性论证站不住：让短 run 不像巧合的是**容差**（两条独立行的逐列比值散布在
O(0.1–1)，第二列落进 `_SHORT_ROW_RTOL` 约 1e-4），与数值大小无关。精度下限的真正职责是另一件
事——整数 / 粗网格数据落在够密的格点上会制造精确巧合，那是容差论证覆盖不到的。

**3. 实测口径（本地 212 份真实补充材料，不入库）**：命中文件 20→22，总 finding 312→307
（**+11 / −16**）。增的 11 条集中在 2 份文件（其中一份是已撤稿的公开数据集）。减的 16 条里，
12 条来自同一份补充材料在语料中重复出现的 4 个副本（每份 −3）：候选池变密后 `_same_band`
正确识别出那本是同一条连续 band；另外 4 条是 GO/GSEA 富集表的量化统计网格被 `_rare` 正确判为
常见值。运行时间不变（190s vs 195s）。

**4. 顺带修好的一处耦合(原本会带进来一个残留)**:精度闸同时决定一对行由**哪一个 pass** 判定。
pass 1 一律丢弃同 band 的行对;pass 2 对**紧邻**行对会再问一句——比值覆盖的是子区间(复制片段)
还是整行(曲线台阶)。闸门改成数小数位之后,「精确但数值小」的除数行(3 位小数、全部 <10)会从
pass 2 落到 pass 1,这类紧邻的部分比率就不再报出。

补法试了四种,前三种按实测否决(语料改动前 312 条):

| 补法 | 结果 |
|---|---|
| 给 pass 1 加上同一条子区间判据 | **582** 条,多张 sheet 顶到 result cap |
| 同上,但只放开紧邻行对 | **460** 条,仍有 sheet 顶到 cap |
| 用「谁记录得更粗」的**精度梯度**决定 pass 归属 | **346** 条、无损失,但新增 39 条**全部**是 3 列最短 run 的紧邻行对,数个 k 与 1.0 相差不到 0.3%——曲线台阶。梯度会把普通面板上 **37%** 的紧邻行对放进 pass 2(原本是 0%),等于换了个方式扩定义域 |
| **采纳**:pass 归属改用**相对单位**问——「这一格靠自己能不能把比值钉到 `_SHORT_ROW_RTOL`」 | **307 条 / 22 文件,与只改闸门时逐文件完全一致**,零新增零损失,残留补上 |

关键在于:`sig ≥ 5` 与 `_SHORT_ROW_RTOL = 1e-4` **本来就是同一条门槛的两种写法**(相对量化步长
`10^-frac/|v| ≤ RTOL` ⟺ `sig ≥ 5`,各量级各小数位都精确成立)。所以这里要问的是两个不同的问题,
必须用两种单位:

- 「这个格点会不会制造精确巧合?」→ **绝对**小数位 → `_is_short_hp`(run 成员资格)
- 「这一格靠自己能不能钉住比值?」→ **相对**量化步长 → `_can_pin_a_ratio`(pass 归属)

老代码用一个判据同时回答两个问题,才会出现「改了 run 闸门,pass 归属跟着悄悄动」。拆开之后,
`4.213` 落进 pass 2 不是量级又漏回来了,而是它自己的量化步长(2.4e-4)确实粗于判定容差(1e-4),
本来就钉不住比值、需要精确的被除数来钉——这正是 pass 2 的前提。

**5. 另一处仍未覆盖的残留**：2 位小数的面板仍在检测范围外——`frac ≥ 3` 挡住它，而且按面板精度重新
取整后，小数值的比值抖动会超过 1e-4 容差，光放宽闸门也救不回来。要覆盖得让容差随每格的记录量化
误差走。

**6. 顺带查明、但本次未处理**：`detect_short_row_reuse` 在一张「按构造成比例」的表（每行都是彼此
的标量倍，如乘法表）上会一次报出 60 条、顶满 finding cap。**顶满 cap 这件事在 main 上就已经如此**，
但**本次改动把它的起始规模压低了**，这一点必须说清楚（合成乘法表，`vals[2]=vals[0]`）：

| 表 | main | 本次改动后 |
|---|---|---|
| 8×4 | 0 | **12** |
| 12×4 | 0 | **32** |
| 20×6 | 25 | **60**（顶 cap） |
| 40×8 | 60 | 60 |

也就是说：小表上这是本次引入的**新**误报面（8 行的表报出 12 条，比它的数据行还多）。真实语料上未
出现这种爆发（净 −5），但形态本身存在。

另外试过用「整行比例族」抑制这个形态，否决了：它在这 212 份真实文件上一次都没触发，且会把最强的信号
形态——一行被复制并缩放进 5 个以上面板——整片吞掉。根因另在：`_same_band` 用「是不是候选行」代替
「是不是数据行」，一张连续表里若干行因精度不够而落选，就把一个 band 读成了多个。这条单独处理。
