# 设计：短行比例复用改用统一的量化重建与预测信息量

- 日期：2026-07-30
- 状态：设计已收敛，待实现计划
- 涉及：`detect_short_row_reuse` 的 `scaled_row_reuse`（ratio）臂
- 不涉及：`identical_row_reuse`、`offset_row_reuse` 与长段检测器的判定改造

> ⚠️ 中立措辞红线：本检测器产出的是**统计信号 / 数据不一致 / 待作者澄清 / data
> inconsistency**，不构成对任何人的指控。原始记录、图注、Methods、作者答复与期刊/机构复核才能
> 定性。文档、代码、变量名、报告文案一律遵守此红线。

---

## 1. 决策摘要

当前 `detect_short_row_reuse` 只允许每格至少记录到 3 位小数的值进入短比例 run。这个逐格硬门槛没有
同时考虑记录精度、值域和确认列数，因此会漏掉「8 列、2 位小数」这类比「3 列、高精度」更强的关系。

本设计不新增一个「2 位小数探测器」，也不把现有 `>=3` 位小数逻辑视为正确基线。ratio 臂改成一条覆盖
所有记录精度的统一路径：

1. **关系成立**：是否存在一个常数 `k`，使 `A × k` 按 B 行的有效记录精度重新取整后，能逐格重建 B。
2. **证据强度**：除去确定 `k` 的一个格子后，剩余格子一共被这个常数预测了多少信息。
3. **结构解释**：这是跨面板的孤立比例关系，还是同一曲线、单位换算、量化网格或整张比例表的构造。

关系由「量化区间有共同交集」严格定义；强度用 `prediction_bits` 表示；结构解释在关系发现之后做，不再
由精度候选池间接决定。

本设计明确否决原方案的 sheet 经验分布概率：

```text
p_i = sheet 中落在预测窗口内的值数 / sheet 数值总数
E   = n_tests × Πp_i
```

它在小表中必然把被匹配的 `b_i` 自己计入窗口，实际 `p_i >= 1/N`，与原方案按量化格点计算的例子不一致；
同时还要求行内各列近似独立，并把多面板、多量纲数据混成一个背景分布。`chance_expectation` 因此不能按
其名字解释为可靠的偶然概率。

## 2. 问题与已知证据

### 2.1 当前硬门槛把精度当成逐格资格

ratio run 的每个格子目前必须满足：

```text
fractional_digits >= 3
```

这与 run 有多少确认列无关。一格被挡掉还会把连续 run 截断，可能让两边都短于最低列数。

前一轮 #56 已把两个问题拆开：

- `_is_short_hp`：格子是否能进入 run；
- `_can_pin_a_ratio`：相邻行对由哪个 pass 处理。

但它们仍围绕固定精度和固定容差工作，而且 `_is_short_hp` 还间接决定候选行、`_rare` 的背景池和
`_same_band` 的 band 成员。改变精度范围会改变表格结构解释；历史实测中，改用所有数据行定义 band
曾令语料产出减少 61%。所以这次不能再把「放宽一个谓词」当作局部修改。

### 2.2 低小数位覆盖数字需要重新核实

本地 212 份补充材料中，含至少 30 个非整数值的数值表按**中位小数位**统计：

| 中位小数位 | sheet 数 | 占比 |
|---|---:|---:|
| 0–2 位 | 170 | 23.7% |
| 3 位 | 80 | 11.1% |
| 4 位 | 61 | 8.5% |
| >=5 位 | 407 | 56.7% |

这证明大量表以 0–2 位小数为主，但不能单凭中位数推出这些 sheet 对当前检测器「完全不可见」：一个中位数
为 2 的表仍可能有足够多的 3 位以上数值组成候选行。

**已直接测量（2026-07-31）**，按当前 `_short_row_candidates` 实际产出的候选行数统计：

| 中位小数位 | sheet 数 | 无任何候选行 | 不足 2 行（凑不出行对） |
|---|---:|---:|---:|
| ≤2 位 | 170 | 124 (73%) | **129 (76%)** |
| 3 位 | 80 | 11 (14%) | 11 (14%) |
| 4 位 | 61 | 8 (13%) | 8 (13%) |
| ≥5 位 | 407 | 82 (20%) | 82 (20%) |
| **合计** | **718** | **225 (31%)** | **230 (32%)** |

修正结论：真正凑不出任何 ratio 行对的是 **129 / 718 ≈ 18%**，不是 23.7%。原表述已作废。

**同时暴露出一件两版设计都没写到的事**：全部数值表里 **31% 没有任何候选行**，其中 **≥5 位小数的表
也占 82 个（20%）**。也就是说压缩覆盖面的不只是精度闸，还有 `_vector_is_patterned`、distinct 值下限
和轴标签正则。若不把这一维拆开，非精度原因造成的缺口会被误记到精度头上，并让本设计的收益被高估。

**排除原因分层归因（已测量，2026-07-31）**。对 225 个无候选行的 sheet，按「排除掉最多行的那一级」
归因，并把原先合在一起的「精度不足」拆成两件不同的事：

| 主导原因 | sheet 数 | 占比 | 本设计能否恢复 |
|---|---:|---:|---|
| `values_not_precise_enough`（有 ≥3 个数，但不够精） | 122 | 54% | **能** —— 正是要拆掉的精度闸 |
| `row_too_sparse`（整行不足 3 个数值） | 93 | 41% | **不能** —— 与精度无关 |
| `axis_label` | 10 | 4% | 不能 |

**这条修正很重要**：原先合并统计时 96% 都记在「精度不足」名下，看起来精度闸解释了几乎全部缺口。
拆开后只有 **54%** 是精度问题。≥5 位小数的 82 个无候选 sheet 正是这条的证据——它们不可能受精度限制，
是行本身太稀疏（`_SHORT_ROW_MIN_COLS` 要求一行至少 3 个数）。

**但「主导原因」不等于「阻塞原因」,上面这张表不能当覆盖上限用。** 一张 sheet 里大多数行因稀疏被排除,
仍可能有两行只栽在精度上。正确的问法是**反事实**:只移除精度资格、其余条件(数值个数、distinct、
pattern、轴标签)全部保留,有多少 sheet 能得到 ≥2 条候选行?已实测:

| 口径 | sheet 总数 | 当前零候选 | **只移除精度闸后可达 ≥2 行** |
|---|---:|---:|---:|
| 按路径 | 718 | 225 | **142** |
| **按文件内容去重** | **597** | **195** | **121** |

（语料 212 个路径里有 45 个是字节级重复副本，实际只有 **167** 份不同内容；后续所有语料数字都同时报
两种口径。）

在 142 个可达 sheet 中，有 **19** 个（去重口径）此前被归类为「行稀疏主导」——这正是「主导 ≠ 阻塞」的
直接证据。所以：

- **可恢复的候选覆盖是 142（去重 121），不是 122**；
- 而 142 仍然只是「能凑出行对」，**不等于会产生 142 条统计信号**。真实产出要等 M2 的 shadow 扫描。

**第三项已测量（2026-08-01）**：有候选行、但关系因中间低精度格被**截断**的情况。做法是对同一对候选行
跑两次现有扫描器——一次用出厂的逐格精度判据，一次只要求格子有限且非零——其余一切不变，所以差异可
完全归因于精度闸：

| 指标 | 实测（去重语料） |
|---|---:|
| 检查过的候选行对 | 609,121 |
| **放开精度闸后 run 变长的行对** | **20,651（3.4%）** |
| 涉及文件 | **33 / 167** |
| 我方 pair 扫描自身触顶的文件 | 30（如实记录，见下） |

**这是与「盲区」不同的另一条证据**：精度闸不只是把整张表挡在门外，它还在**已经被扫描的表里**把关系
截短。

⚠️ **但这 20,651 不能读成「20,651 条被漏掉的信号」。** 放开精度闸同时也放进了粗精度格子，而粗精度格
本来就更容易偶然对上；run 变长既可能是恢复了真关系，也可能是接上了噪声。**区分这两者正是 M2 的评分
要回答的问题**，M0 只负责把量摆出来。

### 2.3 一个当前会漏的强关系

合成面板（B 是 A 统一乘以常数后写回到 2 位小数）：

```text
          Rep1    Rep2    Rep3    Rep4    Rep5    Rep6    Rep7    Rep8
Vehicle  42.13   58.91   19.37   71.20   33.84   26.55   49.02   61.78
Treated  35.43   49.54   16.29   59.87   28.46   22.33   41.22   51.95
逐列比值 0.84097 0.84094 0.84099 0.84087 0.84102 0.84105 0.84088 0.84089
```

取 `k ≈ 0.840916` 时，8 个 `k × A` 全都能四舍五入回对应的 B；最大预测误差约为 0.0037，小于
2 位小数的半个末位单位 0.005。逐列允许的 `k` 区间还有共同交集：

```text
0.840869 <= k <= 0.840941
```

这条关系有一个用于确定 `k` 的格子和 7 个确认格。当前输出为空；相反，3 位以上小数、只有 3 列的关系
可以报告。强弱顺序因此颠倒。

### 2.4 已测误报面

原设计在 40 张表 × 30 行 × 8 列的合成台架上观察到：

| 数据形态 | 小数位 | 连中3列 | 连中4列 | 连中5列 | 连中6列 |
|---|---:|---:|---:|---:|---:|
| 跨两个数量级（1–100） | 1 | 1 | 0 | 0 | 0 |
| 百分比（0–100） | 1 | 0 | 0 | 0 | 0 |
| 小量程读数（1–20） | 1 | 2 | 0 | 0 | 0 |
| 归一化值（集中在 1.0 附近） | 1 | 1867 | 286 | 40 | 6 |
| 归一化值 | 2 | 33 | 1 | 0 | 0 |
| 归一化值 | 3 | 0 | 0 | 0 | 0 |
| 同一条平滑曲线上的行 | 1 | 16549 | 14487 | 10904 | 6381 |
| 同一条平滑曲线上的行 | 2 | 5180 | 1710 | 467 | 85 |
| 同一条平滑曲线上的行 | 3 | 76 | 4 | 1 | 0 |

这说明：

- 低精度本身不是主要误报源；
- 值域相对量化步长过窄时，预测一个格子的意义很小；
- run 越长，一个常数解释的确认格越多；
- 平滑曲线不是独立随机值，任何只靠独立零假设的概率都会误读，必须由结构上下文解释。

## 3. 设计原则

### 3.1 一个 ratio 路径覆盖所有精度

不按 0、1、2、`>=3` 位小数分支，不保留「旧高精度路径 + 新低精度路径」的最终结构。开发期间可以让
新旧算法 shadow 并行以比较输出，但正式切换后旧 ratio 两个 pass 删除。

### 3.2 把三类问题分层

| 层 | 回答的问题 | 不负责什么 |
|---|---|---|
| 量化重建 | 一个 `k` 能否逐格重建目标行 | 不判断是否值得报告 |
| 预测信息量 | 这个 `k` 解释了多少确认信息 | 不解释曲线、单位或表格语义 |
| 结构分类 | 关系在表中的上下文是什么 | 不改变数学上是否能重建 |

任何一层都不得再通过「是否为高精度候选」暗中改变另一层的输入。

### 3.3 旧语料输出是比较基线，不是真值

当前 307 条 / 22 文件用于定位行为变化，但验收不要求净数量不变。每一条丢失和新增都要逐文件解释；
已提交的强关系 fixture 必须保留，除非经结构证据证明它属于另一种明确关系类型，并同步修改设计和回归
测试。不得只因为总数相同就接受一组 `+N/-N`。

回归硬锚点分两层：

1. 仓库已提交的强关系 fixture；
2. gitignored 的本地锚点清单，只收录 #56 新覆盖中已经独立人工复核、确认可被同一个 `k` 逐格重建且
   不属于当前已知结构解释的**具体候选**。

第二层不把整份文件的全部现有输出锁成真值，也不得把论文是否撤稿作为候选标签；撤稿状态与某个具体数值
关系是否构成高置信统计信号是两个独立问题。本地清单只保存复核所需的候选身份与预期 context，不把真实
数据、DOI 或复核判断提交到 git。两层锚点都必须在原始 sheet 规模下继续过门槛并得到预期结构分类，
否则阻塞正式替换。

**⚠️ 截断如实记录（2026-08-01）**：上述扫描并非完整扫描。在 167 份去重语料上，
`detect_short_row_reuse` 报告了三类放弃：

| 截断类型 | 事件数 | 涉及文件 |
|---|---:|---:|
| `detector_candidate_pool_limit`（候选行池触顶 400） | 21 | 21 |
| `detector_compute_budget_limit`（计算预算耗尽） | 8 | 8 |
| `detector_finding_limit`（finding 数触顶） | 2 | 2 |

**约 17% 的文件（29/167）扫描被截断。** 因此下面「当前输出里没有超过 5 列的 ratio」这句话，严格说是
**关于一次部分扫描**的陈述，不能当作对整个语料的结论。

**另外，按路径统计会显著放大结果**。同一份补充材料在语料里最多出现 5 个副本，去重前后：

| kind | 按路径（212） | **按内容去重（167）** |
|---|---:|---:|
| `identical_row_reuse` | 109 | 108 |
| `scaled_row_reuse` | 122 | **77** |
| `offset_row_reuse` | 76 | **24** |

ratio 臂的真实规模是 **77 条而不是 122 条**，offset 臂是 24 而不是 76。后续所有数字以去重口径为准。

**已测量（2026-07-31）：第二层锚点的指定来源是空的。** #56 在语料上的新增**全部是
`identical_row_reuse`**（+11 分布在 2 份文件），而 ratio 臂按 §5.2 明确不报 `k≈1`。#56 对 ratio 臂的
净效果是 **−8**（130 → 122）。因此「从 #56 新覆盖里挑 ratio 锚点」这条路取不到任何候选。

改用当前 detector 在语料上的 122 条 ratio 输出作为候选池，按 run 长度、`k` 离 1 与离整十次幂的距离
排序后，整体画像是：

| 指标 | 实测 |
|---|---|
| ratio finding 总数 | 122 |
| run 长度分布 | 3 列 **71** 条、4 列 **48** 条、5 列 **3** 条、更长 **0** 条 |
| 最长的 3 条（5 列）的 `k` | 0.9977 / 0.9980 / 0.9980 —— **全部落在 1.0 的 0.3% 以内** |
| `k` 在 1.0 的 1% 以内 | 14 / 122 |
| 次强一档（4 列、`k≈0.8286`） | 集中在同一份补充材料的 4 个副本上，实际只有个位数条不同关系 |

**能下的结论只有这一条**：

> 当前 detector **已扫描到的输出**中，没有超过 5 列的 ratio；**尚未建立经人工确认的真实 ratio 锚点**。

**不能**下成「语料中不存在强 ratio 关系」。理由是直接的：

1. **当前 detector 按构造就看不到目标关系**（低精度被精度闸挡在门外），所以它的输出不能用来证明目标
   关系不存在——这是循环论证；
2. 122 条候选**全部仍是 `UNREVIEWED`**，没有任何一条经过人工结构核对；
3. 重跑时存在多次 candidate cap 与 budget exhaustion 截断，而这些截断**没有进入汇总**，所以连"已扫描
   到的输出"本身都不完整；
4. `k` 接近 1 只能说**与曲线台阶相符**，在核对结构之前不能直接断定它就是曲线；那组 4 列、`k≈0.8286`
   的去重候选同样尚未检查。

因此实事求是的表述是：**预期产出目前只有合成立论支撑，尚未被真实语料证实，也尚未被真实语料否证。**
M4 的验收在锚点建立之前只能是 fixture 级的，结论必须按该规模措辞。

在此基础上，锚点条数仍是必须报出来的数字。** #56 的新增覆盖只有 11 条、分布在 2 份文件里，人工复核后
能进第二层清单的很可能是个位数。若最终锚点数很少，M4「强锚点全部保留」所能提供的信心是相应有限的，
必须在 M0 就把条数写下来，而不是等到 M4 才发现验收基础比预想的薄。锚点数少不阻塞实施，但要求 M4 的
结论按这个规模如实措辞，不得表述成已获得广泛真值验证。

## 4. 有效记录步长

### 4.1 为什么不能直接数 float 的小数位

`Sheet` 当前只保留 float 数值。`71.20` 和 `71.2` 进入检测器后完全相同，原始末尾零已经丢失。因此本版
不能声称知道「该单元格原本记录到几位小数」。

本设计先使用**行级推断的有效记录步长**，不扩大到解析 Excel 样式或保存 CSV 原始词法；报告必须明确
它是推断值。

### 4.2 确定性推断规则

对一行参与比较的有限数值：

1. 用现有的十进制 float 表示逻辑计算每格可见小数位 `d_cell`，最多计 10 位。
2. 取该行所有有限数值 `d_cell` 的众数为 `d_row`；众数并列时取较大的小数位。
3. 每格有效小数位：

```text
d_eff(i) = max(d_cell(i), d_row)
q_i      = 10 ** (-d_eff(i))
```

`max` 的含义是：同行大多数值为 2 位小数时，把 float 中的 `71.2` 保守地读成同一面板精度的 `71.20`；
若一格确实保存了更多小数，不把它降粗。

**⚠️ 「推断错了只会少报」这个说法只对匹配阶段成立，对计分阶段不成立。** 若真实 `q=0.1` 而被推断为
`q=0.01`：允许区间确实变窄（少匹配），但**任何仍然匹配上的 run 会被按更细的格点计分**——`G_i = R/q_i`
每细十倍就多 `log2(10) ≈ 3.32` bits/确认格，5 个确认格就是 16.6 bits，足以把候选推过 20-bit 门槛。

更极端的是**单格**就能主导：一个公式缓存值（如 `1/3`）落在整行 2 位小数中间，会被读成 `q=1e-10`，
比邻居细 8 个数量级，**单格贡献约 38 bits**，独自越过门槛。Excel 的公式缓存值与显示格式不一致时，
"float 里小数位更多"并不代表真实记录精度更高。

所以 `_effective_row_quantums` 只能作为 **M1 的输入假设**，不是安全性保证。**M2 必须**：

- 比较不同 quantum 推断下的 score margin（敏感性分析）；
- 给单格可贡献的 bits 设上界，或对计分改用行级步长而非逐格步长。

`tests/test_row_quantum.py::test_one_float_artifact_cell_can_out_resolve_its_whole_row`
把这个隐患钉住。

全整数行得到 `d_row=0, q=1`，不再因整数身份被绝对排除。短小计数矩阵的有效格点很少，会由
`prediction_bits` 得到低分；长段、宽值域且可由一个常数逐格重建的整数行则可以成为待复核统计信号。

finding 写入：

```text
precision_source = "row_inferred"
quantum_a
quantum_b
```

这里的 `quantum_a/quantum_b` 是 run 内有效步长的排序去重摘要；不是虚构的原始格式元数据。

## 5. 统一量化重建核

### 5.1 使用有方向的生成模型

对每个无序行对同时检查两个方向：

```text
A -> B：B 可能由已有的 A 乘以 k 后，按 B 的有效精度写回
B -> A：A 可能由已有的 B 乘以 k 后，按 A 的有效精度写回
```

源行数值按当前存储值使用；只有目标行承担写回量化误差。这比把 A、B 都当作某个未知潜在向量的独立
取整更符合本检测器寻找的「复制后统一缩放」关系。因果方向未知，所以两个方向都检查。

### 5.2 每列给出一个允许的 `k` 区间

对方向 `A -> B`，若 `a_i` 有限且非零、`b_i` 有限，目标步长为 `q_bi`：

```text
lo_i = (b_i - q_bi/2) / a_i
hi_i = (b_i + q_bi/2) / a_i
I_i  = [min(lo_i, hi_i), max(lo_i, hi_i)]
```

浮点比较只允许一个固定的机器误差余量，不再另设随小数位变化的 `_SHORT_ROW_RTOL`。

特殊情况：

- `a_i = 0, b_i != 0`：关系在该列断开；
- `a_i = 0, b_i = 0`：与任意 `k` 相容，但不缩窄区间、不增加确认信息；
- NaN / 非有限值：关系断开；
- `k` 的共同区间包含 1：在当前量化精度下无法区分于无缩放，ratio 不报告；identical 臂独立判断；
- `k` 接近整十次幂：交给单位换算结构分类。

### 5.3 连续 run 是区间共同交集

连续列 `[s, e]` 构成比例 run，当且仅当其所有有信息列满足：

```text
max(lo_s ... lo_e) <= min(hi_s ... hi_e)
```

内部候选至少需要：

- 2 个有信息列：一个确定 `k`，至少一个确认；
- 2 个不同的源值；
- run 长度 `< _ROW_REL_MIN_COLS`，保持与长段检测器的职责边界。

最低 2 列是关系可检验性的定义，不是最终报告门槛；是否报告由 `prediction_bits` 决定。扫描器返回所有
不被更长同向 run 包含的 maximal runs，再由证据分数选择同一行对的代表关系。

一个行对可能同时有多个 maximal run。选择顺序固定为：

1. `prediction_bits` 较高；
2. 有信息确认列较多；
3. run 较长；
4. 起始列较早；
5. 方向按规范化行坐标排序。

由共同区间选择最终 `k` 时，取使最大标准化写回误差最小的点；若最优点不唯一，取最优区间中点。报告：

```text
ratio_interval = [k_lo, k_hi]
ratio
max_rounding_residual
```

其中：

```text
rounding_residual_i = abs(b_i - k*a_i) / q_bi
```

区间定义保证有信息列的残差不超过 `0.5 + machine_epsilon`。

## 6. 统一证据强度：prediction bits

### 6.1 人工判断的形式化

人工看到一条比例关系时，实际在做：

1. 用一个格子估计 `k`；
2. 用同一个 `k` 预测其余格子；
3. 看预测跨越多少不同数值、精确到哪个量化格点、连续成功多少次。

`prediction_bits` 把「一个参数解释了多少后续记录」写成信息压缩量，而不是声称得到精确 p 值。

### 6.2 目标行的有效格点数

对目标 run 的非零有信息值，定义稳健范围：

```text
R = max(median(q_bi), percentile90(b_run) - percentile10(b_run))
```

百分位使用确定性的线性插值。每个确认格在这个范围内大约有：

```text
G_i = max(1, R / q_bi)
```

个可区分量化位置。若数据集中在 1.0 附近且只记录到 1 位小数，`G_i` 很小；若数据跨越几十个单位并记录
到 2 位小数，`G_i` 可达数千。

### 6.3 分数

run 的第一个有信息格作为 anchor，不计预测收益。其余有信息格贡献：

```text
raw_prediction_bits = Σ log2(G_i)
```

一张 sheet 的实际搜索机会数按已进入 pair loop 的行对确定。若行对的重叠宽度为 `m_pair`，两个方向各有
`m_pair - 1` 个能容纳至少两列的潜在起点；即使某个起点随后立即被 NaN、零或文本打断，也仍计入搜索
成本：

```text
n_tests =
    2 × Σ实际检查的无序行对 max(0, m_pair - 1)
```

系数 2 是两个生成方向。若候选池或计算预算提前截断，只统计实际检查过的机会，并照常记录 coverage 不完整。

最终：

```text
prediction_bits = raw_prediction_bits - log2(max(1, n_tests))
```

默认报告门槛：

```text
PAPERCONAN_SHORT_ROW_MIN_PREDICTION_BITS = 20
```

20 bits 表示在扣除搜索描述成本后，这个单一比例模型至少节省约一百万分之一量级的网格编码空间；它是
可比较的模型压缩分数，不命名为概率，也不解释为对原因的定性。

M2 必须在语料和零假设台架上验证 20 bits。若它不能同时满足 M2 验收，停止并修订本设计；不得在实现中
无记录地调到一个刚好通过当前语料的数字。

### 6.4 强弱顺序

同一公式自然同时使用：

- 确认列数；
- 记录步长；
- 相对值域；
- 实际搜索次数。

§2.3 的 8 列 2 位小数例子约有 7 个确认格，每格覆盖数千个可能位置，扣除小表搜索成本后仍远高于
20 bits。3 列高精度关系只有 2 个确认格；它仍可能超过 20 bits，但分数应低于前者。M2 用固定 fixture
直接断言：

```text
score(8列、2位小数) > score(3列、高精度)
```

### 6.5 表大小敏感性必须量出来

`-log2(n_tests)` 有意惩罚更大的搜索域，所以同一条关系放进更大的 sheet 后会降分。这在多重搜索意义上
合理，但会带来检出能力差异，不能只验证小面板。

M2 必须产出：

- 212 份语料的 `n_tests` 与 `log2(n_tests)` 分布；
- 所有 shadow 候选相对 20-bit 门槛的 margin 分布，并按 sheet 行数分层；
- 把完全相同的 planted relation 嵌入 2、10、30、100、400 行无关背景后的 padding 曲线；
- 每个 committed / 本地强锚点在原始 sheet 规模下的 raw bits、搜索惩罚与最终 margin；
- 每个锚点在 padding 曲线中第一次跌破 20 bits 的行数。

padding 实验用于决定惩罚应继续按整 sheet、structural block 还是 block pair 计，不预设结果。任何强锚点
在其**原始 sheet 规模**下跌破门槛都直接阻塞；不得通过 cap `n_tests` 或按当前 fixture 特调门槛绕过。

### 6.6 两列 run 的显式边界

两个目标值 `x < y` 在线性百分位定义下满足：

```text
percentile90 - percentile10 = 0.8 * (y - x)
```

所以两列 run 不会一律退化；但当目标值相同或只差一个量化格时，`R` 会被 `median(q)` 托到约 `q`，
`G_i=1`，唯一确认格贡献 0 bits。这应是可见、固定的拒绝行为。

M2 固定测试目标值：

- 相同量化格；
- 相邻 1 个量化格；
- 相隔 2、10、100 个量化格；
- 源值不同但目标值因取整相同；
- 两个生成方向各自的 `R`、`G_i` 和最终分数。

相同或相邻量化格的两列候选不得过 20-bit 门槛；若未来改变百分位或 `R` 定义，这组测试必须变红。

## 7. 结构分类与误报控制

### 7.1 ratio 候选行不再由精度决定

ratio 臂的数据行最低定义：

- 至少 2 个有限、非零数值；
- 至少 2 个不同数值；
- 行标签不像坐标轴或索引；
- 候选生成不调用 `_is_short_hp`。

候选池仍受 `_SHORT_ROW_MAX_ROWS_PER_SHEET` 和 `_SHORT_ROW_BUDGET` 约束，截断必须写 coverage。M3 必须
测量扩大候选域后的候选数、预算耗尽率和运行时间。

`identical` / `offset` 臂暂时继续使用现有候选定义；这不是按精度复制 ratio 探测器，而是三个关系类型
暂时拥有各自的数学资格。ratio 只有一条覆盖所有精度的路径。

### 7.2 布局结构独立于 ratio 精度

为 ratio 上下文建立 `row_layout`：

- 一行有至少 2 个有限数值且至少 2 个不同数值，即可作为数值数据行；
- 空白行、纯文本标题行和轴标签行是分隔行；
- 连续数据行组成 structural block；
- block 成员不读取 `_is_short_hp`、`prediction_bits` 或是否形成 finding。

这替换 ratio 臂当前由候选行集合反推 `_same_band` 的做法。

### 7.3 关系发现后再分类

量化重建和 `prediction_bits` 先产生 qualifying relation，随后分类：

| context class | 判定 | 处理 |
|---|---|---|
| `isolated_cross_block_ratio` | 两行分属不同 structural block，关系孤立 | 输出待复核统计信号 |
| `partial_within_block_ratio` | 同 block，但只覆盖部分可比较列 | 先进入 block 内关系图；只有未被系列/比例族解释的孤立边才输出 |
| `within_block_global_scale` | 同 block 且覆盖 >=85% 可比较列 | 先进入 block 内关系图，再按下述确定顺序处理 |
| `proportional_series` | 邻近多行在相同列域形成连续比例关系 | 作为曲线/序列结构解释，不输出 pair finding |
| `proportional_family` | 同一 block 内比例关系图密集 | 输出至多一条 `medium` 表级模式，禁止逐对占满 finding cap |
| `power_of_ten_conversion` | `k` 在量化区间内与 `10^n` 相容 | 作为单位重述，不输出孤立复用 |
| `quantized_common_pool` | run 值来自高频量化网格/平台 | 不输出孤立复用 |

系列与比例族使用确定性的 block 内关系图：

- 节点是 structural block 中的数据行；
- 所有过 20 bits 的同 block qualifying relation 都形成边，并保留它是 partial 还是 global；
- 两条边属于同一列域，当且仅当它们的 run 至少重叠 2 个有信息列，且交集长度至少为较短 run 的 50%；
- `proportional_series` 是至少 3 个连续数据行组成的链，链上每一对相邻行都有同列域边；
- `proportional_family` 是至少 4 个节点的连通分量，且无向边密度
  `2E / (V*(V-1)) >= 0.5`；
- 同一分量同时满足两者时，密集的 `proportional_family` 优先；否则连续链按
  `proportional_series` 处理。

block 内 edge 的处理顺序固定为：

1. 先折叠所有 `proportional_family`，使用既有 `scaled_row_reuse` kind、`medium` severity 和
   `context_class="proportional_family"`，每个分量至多一条；
2. 剩余边中的 `proportional_series` 作为曲线/序列结构解释，不输出链内 pair finding；
3. 剩余的相邻 global-scale edge 即使没有形成 3 行链，也作为单步曲线/全局缩放解释，不输出 pair
   finding；
4. 剩余的非相邻、非密集 global-scale edge 以
   `context_class="within_block_global_scale"` 输出，不能仅因同 block 而静默删除。
5. 剩余的 partial edge（包括没有形成系列的相邻 partial edge）以
   `context_class="partial_within_block_ratio"` 输出；这保留 #56 已覆盖的相邻部分区间关系，但其最终
   数量仍受 §7.5 的曲线阻塞闸约束。

两类聚合都以 structural block 为边界。跨多个明确分隔面板的 qualifying relation 永远不因 block 内图
密集而删除。以跨 block 关系为边再建一张图：单边输出普通 `isolated_cross_block_ratio`；含至少 2 条边
的连通分量折叠成一条跨面板统计信号，并保留 block 数、行数、边数与示例行。

### 7.4 现有结构守卫的迁移

- `_near_power_of_ten`：改为判断 `ratio_interval` 是否包含整十次幂，而不是只比较均值与固定 RTOL。
- `_rare`：继续防量化网格，但频率池改为 source / target 各自 structural block 的全部 ratio 数据行，
  并按各自有效量化步长归桶；任一侧来自高频共同池就分类为 `quantized_common_pool`，不再只统计
  `_is_short_hp` 候选。
- `_vector_is_patterned`：保留为行语义特征；等差/等比坐标行不进入孤立 ratio 输出。
- `_same_band`：ratio 臂删除，职责由 `row_layout` 和关系后的 context class 接管。

### 7.5 曲线台架是带数字的阻塞闸

20 bits 不能单独解释曲线。以 30 行 × 8 列、每个确认格约 9 bits 的 2 位小数曲线为例：

```text
n_tests                 = 2 * C(30, 2) * 7 = 6090
log2(n_tests)            = 12.57
3列 prediction_bits     ~= 2 * 9 - 12.57 = 5.43
6列 prediction_bits     ~= 5 * 9 - 12.57 = 32.43
```

6 列部分匹配会越过 20 bits；因此必须由关系图和 context classification 处理，不能宣称分数自己兜住。

**M0 已冻结（2026-07-31）**，生成器在 `recheck/sigplan/bench.py`（gitignored），baseline 在
`recheck/sigplan/curve_baseline.json`，一条命令重跑：`uv run python recheck/sigplan/curve_baseline.py`。

冻结过程中发现原台架有一个盲点，已修正：**曲线数据若整块连续，当前的 band 守卫会把整块视为一个 band
并整臂压制，最终孤立输出恒为 0**，于是台架根本测不到「同一条曲线被写成若干面板」这种最常见、也最可能
在替换 band 守卫后回归的布局。新增 `curve_paneled` 形态（每 5 行插一个分隔行）后：

| 形态 | 当前 detector 最终孤立 `scaled_row_reuse` |
|---|---|
| `curve/1`、`curve/2`、`curve/3`（连续） | 0 |
| `curve_paneled/1`、`curve_paneled/2` | 0（被精度闸挡住） |
| **`curve_paneled/3`** | **16**（run 长度 3 有 15 条、4 有 1 条） |

也就是说**当前实现在分面板的曲线数据上已经在产生误报**，只是 1–2 位小数被精度闸顺带挡住了。本设计
放开 1–2 位小数后，这一路必须由结构分类接住，否则会成倍放大。§7.5 的阻塞不等式因此有了非零基线：
`curve_paneled/1` 与 `/2` 必须为 0，`curve_paneled/3` 按 run 长度分层不得超过 15 / 1。

M3 同时记录：

```text
raw_over_20_bits
proportional_series_edges
proportional_family_edges
final_isolated_scaled_row_reuse
```

阻塞条件针对**结构分类后的最终孤立输出**，不是 raw 候选：

```text
final_isolated_new(curve, 1dp) = 0
final_isolated_new(curve, 2dp) = 0
final_isolated_new(curve, d>=3, run_length=L)
    <= frozen_current_baseline(d, L)
```

旧 detector 因精度闸在 1–2 位曲线上的最终孤立输出基线为 0。3 位以上按小数位和 run length 分层比较，
不得用一层减少抵消另一层增加。任一不等式失败都阻塞 M4/M5；只能修正结构分类或回到设计评审，不能静默
提高 20-bit 门槛把曲线问题转嫁给所有数据。

### 7.6 `_same_band` 压制集合必须专项审计

shadow 运行要从旧算法额外导出：

```text
old_same_band_suppressed_pairs
```

它精确定义为：旧 pass 1 的 ratio run 已通过长度、distinct、`_rare` 和 power-of-ten 等其他条件，唯一因
`_same_band` 未输出的行对。对集合中的每一对，新方案必须记录唯一去向：

```text
no_common_ratio_interval
below_prediction_bits
power_of_ten_conversion
patterned_source_or_target
proportional_series
proportional_family
quantized_common_pool
partial_within_block_ratio
within_block_global_scale
isolated_cross_block_ratio
coverage_not_examined
```

专项表按文件、行距、run 长度、`k`、新分数和 context 汇总。所有被新方案重新输出的旧压制行对逐条复核；
所有未输出的行对也必须有上述机器可枚举原因；出现 `coverage_not_examined` 直接阻塞 M4 验收。该集合不得
混进总体 `+N/-N` 后只看净变化。

## 9. 否决的替代方案

### 9.1 为两位小数增加独立路径

否决。它会制造新的 `2 / >=3` 边界、重复候选和守卫逻辑，也无法解释一位小数长段或高精度短段的相对
强弱。shadow 双跑只用于迁移验证，不能成为最终架构。

### 9.2 用 sheet ECDF 计算 `chance_expectation`

否决。原因：

- 被匹配值自己保证 `p_i >= 1/N`，窄窗口下分数退化为 sheet 大小函数；
- 文档示例按理论格点计算，和 ECDF 定义不是同一个模型；
- 多面板 sheet 混合量纲，整表池既不保证保守，也不保证同分布；
- `Πp_i` 要求列间独立，重复测量、时间序列和曲线数据不满足；
- 结构性关系仍需额外守卫，复杂度没有换来可靠概率语义。

### 9.3 每张 sheet 做穷举置换检验

暂不采用。它比 ECDF 更贴近当前数据，但短行 sheet 可用置换太少，无法稳定分辨小概率；破坏列对齐后仍不能
解释同一曲线和共享对照，计算成本也高。保留为离线校准工具，不进入首版运行时。

### M2 实测结果（2026-08-01）—— 分数在噪声上完美，在曲线上无效

在冻结台架上把 M1 的重建核 + M2 的评分连起来跑（k≈1 与整十次幂已按设计排除），每个 run 都是误报：

| 台架 | run 数 | 最高分 | ≥10 bits | ≥20 bits | ≥30 bits | ≥40 bits |
|---|---:|---:|---:|---:|---:|---:|
| **独立随机 wide** 1/2/3 位 | 1387 / 161 / 21 | 3.55 | **0** | **0** | 0 | 0 |
| **百分比** 1/2/3 位 | 352 / 25 / 8 | 3.00 | **0** | **0** | 0 | 0 |
| **小量程** 1/2/3 位 | 1768 / 195 / 21 | 0.98 | **0** | **0** | 0 | 0 |
| **归一化** 1/2/3 位 | 26233 / 3679 / 376 | −1.40 | **0** | **0** | 0 | 0 |
| **曲线** 1 位 | 72695 | 43.12 | 17514 | **10018** | 4432 | 618 |
| 曲线 2 位 | 37142 | 46.17 | 774 | **111** | 14 | 4 |
| 曲线 3 位 | 4433 | 24.43 | 51 | **1** | 0 | 0 |
| **分面板曲线** 1 位 | 72472 | 43.12 | 18082 | **10535** | 4675 | 647 |
| 分面板曲线 2 位 | 37530 | 41.72 | 732 | **92** | 15 | 2 |
| 分面板曲线 3 位 | 4246 | 25.45 | 36 | **1** | 1 | 0 |

**两个结论，方向相反：**

**1. 对「偶然巧合」这一类，分数完全有效。** 四种独立数据形态、1–3 位小数、共约 3.4 万条 run，
**没有一条到 10 bits**，最高 3.55。也就是说 §2.4 里那些靠容差论证担心的巧合，评分能干净地压掉——
1 位小数也压得住。这正是设计想要的效果，而且比预期好。

**2. 对「结构性成比例」这一类，分数无效，且抬高门槛救不回来。** 曲线数据 1 位小数下 **10,018 条**
过 20 bits；抬到 **40 bits 仍有 618 条**。原因不是模型算错了，而是**算对了**——曲线相邻行本来就是彼此
的倍数，压缩是真实的，只是它不构成"被复制"的证据。任何建立在"一个常数解释了多少信息"之上的分数都
无法区分这两者。

**因此本设计的可行性完全押在结构分类（§7.3）上**，而不是押在分数上。分数只解决了两类误报中的一类。

**按记录精度分层看，结论并不一致**（与当前 detector 的冻结基线对比）：

| 精度 | 当前基线（分面板曲线） | 新设计过 20 bits | 判断 |
|---|---:|---:|---|
| ≥3 位 | 16 | **1** | **优于现状** |
| 2 位 | 0 | **92** | 需结构分类接住绝大部分 |
| 1 位 | 0 | **10535** | **结构分类必须做到 ~99.99%，不现实** |

所以 go/no-go 不应是一个二元决定，而应按精度分档。**1 位小数这一档按本设计不可行**，除非结构分类
能给出接近完美的曲线识别；2 位可谈；≥3 位已经能改善。

## 11. 完成后的行为

- 不再存在 ratio 的 `fractional_digits >= 3` 资格线。
- 一位、两位、三位和更高精度共用同一个量化重建定义和同一个 20-bit 报告门槛。
- 8 列 2 位小数可以比 3 列高精度得到更高分。
- 同一条关系可由读者用 `ratio_interval`、有效步长和最大写回误差直接复核。
- 平滑曲线与比例表由结构上下文分类，不被错误包装成独立随机值的极小概率。
- 报告的是统计信号和数据不一致，不是原因判断；共享对照、派生数据、单位换算和表格构造仍需结合图注、
  Methods、原始记录与作者说明解释。
