# 局部段关系检测（local pair runs）设计

**状态**：设计已认可（2026-10-15），待写实施计划。
**一句话**：同一数值块内，两行或两列只在一段连续位置上成恒定比例或恒定差值、段外不成立时，报出一条统计信号。

paperconan 输出的是待解释的数据不一致，不是结论。本检测器报出的每一条，都要结合图注、Methods 和作者说明再判断。

---

## 1. 为什么做

评估集里有一类数据不一致，现有检测器按构造就报不出来：两条测量线（两个时间点、两组动物、两列重复）在一段连续位置上 B = k·A 或 B = A + c，段外不成立。

现有检测器漏掉它的原因各不相同：

- `detect_relations`（列对）：比例和差值只认整列成立；部分段差值要求 n ≥ 24、段长 ≥ max(20, n/2)；比例遇到除数列里一个 0 就整对跳过。
- `detect_row_relations`（同块行对）：只有相同和比例两个臂，没有差值臂；整块要 ≥ `_ROW_REL_MIN_COLS`（12）列。
- `detect_short_row_reuse`（同表短行）：段内每格要 ≥ `_SHORT_ROW_MIN_FRAC_DIGITS` 位小数，第一遍丢掉相邻行对。

**已经排除的路线**：

- **单纯放宽这些闸门**：在本地评估集（不入库）上逐道放宽重扫，只补回少数几张卡，还挤丢了已有的命中。
- **放宽比例容差**（分支 `fix/column-pair-tolerance-v2`）：列对台架上，良性的精确比例家族与真阳性在同一精度档一起翻转。

这两条结论各自的测量方法，见本地评估集 `eval_scope/` 下的 `gate_sweep.py` 与 `compare_runs.py`。容差分不开良性，所以本设计不靠容差，靠**局部性**：

- 曲线族、归一化、单位换算这类良性结构，关系覆盖整条线；
- 复制一段再缩放或平移，关系只在那一段成立，段外立刻散开。

此前一次测量支持这个判据，但测的是另一批数据，所以本项目必须在自己的台架上重新测量（见 §8）。

## 2. 范围

**做**：

- 同一个 `find_numeric_blocks` 块内的**行对**和**列对**；
- 两种关系：**恒定比例** B = k·A，**恒定差值** B = A + c；
- 关系只在一段连续位置上成立，段外不成立。

**不做**（另立项，本设计不为它们预留接口）：

- 整条线都成立的关系（留给现有检测器）；
- 差为整数、差为 10 的倍数；
- 组块对组块（一组多列整体等于另一组乘系数）；
- 行内逐列等差；
- 不在数值块内的两行小组；
- 跨块、跨表。

## 3. 组成

全部放在 `_audit.py`，作为**独立的一遍检测**：检测本身不读写任何现有检测器的候选池、频次表、预算或上限；它的 finding 与其它 finding 一起经过按条数计的输出闸门，其中两道（每块的 finding 上限、整表的 dense 判定）把它当作后来者，其余的不分类型（§7）。现有的 `_effective_row_quantums` 和 `_scan_quantized_ratio_runs` 不改动，也不调用（理由见 §3.1）。

| 单元 | 作用 |
|---|---|
| `_effective_line_quantums(values)` | 每格的记录步长。对整条线判断导出方式：固定小数位，还是固定有效数字。看哪种模式让更多格的位数恰好等于众数；平局取固定小数位。固定小数位时，与 `_effective_row_quantums` 的结果相同，读作 0 的格除外（它取这条线上最细的步长；整条线都没有非零格时才退回行推断的步长）；固定有效数字时，按每格数量级推步长，且不粗于该格自身的位数 |
| `_panelled_line_quantums(values, pieces)` | 整表 extent 上，一条线穿过几个面板，各面板的导出精度可以不同：每个面板那一段按它自己读，不属于任何面板的格合在一起读；重叠的面板，先到者占格，后到者只读剩下的格；一段里没有非零格时，这些格沿用整条线的读法。不分段时，一个精度粗的面板会被下方精度细的面板拉到细步长，区间过窄，跨面板复制的段找不到（Task 13 审查实测） |
| `_symmetric_ratio_interval(a, b, q_a, q_b)` | 两侧都舍入时 k 的可能区间：取 `[a ± q_a/2]`、`[b ± q_b/2]` 四个角之比的最小、最大值。源的区间含 0 时：目标的区间也含 0，返回 `(−inf, +inf)`，即相容但无信息；否则返回 `None`：这时只要 \|k\| 足够大就写得出这一对，可取的 k 是两条射线，一个区间装不下，交给 `_zero_source_miss` 对组的常数逐个判断。`None` 会打断一段 |
| `_zero_source_miss(b, q_a, q_b, k)` | 源读作 0（真值在 `[−q_a/2, q_a/2]` 内）时，常数 k 离写出 b 还差多少，以 B 的单位计：\|k\|·q_a/2 够到 b 的舍入区间就是 0。输入不是有限值时返回 inf，量不出的差距不会被当作写得出 |
| `_symmetric_offset_interval(a, b, q_a, q_b)` | `c ∈ [b − a − (q_a+q_b)/2, b − a + (q_a+q_b)/2]` |
| `_scan_interval_runs(spans, source, min_informative, min_distinct_source)` | 区间逐格求交，求极大连续段。输出与 `_scan_quantized_ratio_runs` 的段落逻辑相同（被另一段包含的段丢弃），但接收现成的区间，比例和差值共用。不同源值只在有信息的格上数。一个窗口沿线滑动、两端只前进，耗时与线长成正比 |
| `_group_constant_runs(runs, spans, admit)` | 同一常数的几段合为一组：长段优先，区间仍相交的段归入同组（位置重叠的两段区间必不相交）。组的常数区间取各段之交；组的**位置**是这条线上区间与组区间相交的格，成不成段都算。没有区间的格（源读作 0）只在 `admit` 判定组内某个常数写得出它时算作位置，且不算有信息的位置。不提供信息的格（比例臂里两侧都读作 0，与任何常数相容）可以留在一段中间，但从每段两端剪掉，不会把一段向外延长 |
| `_outside_departure(a_line, b_line, q_a, q_b, group, spans, relation)` | 组外位置的偏离中位数，扣除舍入能解释的部分（§4 第 2 条）。没有组外的有效位置时返回 `None` |
| 复用 `_ratio_prediction_bits` | 压缩得分：按搜索次数扣减，单格贡献设上限。只看给定的值与步长，与关系类型无关 |
| `detect_local_pair_runs(sheet, r0, r1, c0, c1, header, already, coverage, skip_columns, panels)` | 驱动：枚举行对和列对、两种关系，套用 §4 的判定，产出 finding。`panels` 是整表 extent 上本表的其余块。一个同时持有两条线的块，在它自己的范围上、以它自己的组外有机会比这对线（两条线在那块里都可用时）；在 extent 上把这些位置（值和步长）留空，只在没有这样的块覆盖的位置上读这对线——那是两条线只在整表的长线上相遇的地方。留下的部分必须本身可用：稀释梯度截掉别的面板的格后仍是刻度；可用性不够的线对在扣预算之前跳过。只按一条轴判断“同在一块内”会漏掉跨面板的段：一个横跨两条线的第三块只在它自己的行上比过它们 |

### 3.1 为什么不复用现有的步长推断和比例扫描

在本地评估集上用原型检验，两处现有做法会漏掉本设计要找的形状：

- **步长**：按有效数字导出的表（如统一 7 位有效数字），三位整数的值只有 4 位小数，两位整数的值有 5 位。`_effective_row_quantums` 按整行小数位的众数读，把前者读细了 10 倍，舍入区间过窄，本该成段的被切断。
- **方向**：`_scan_quantized_ratio_runs` 假设只有目标一侧经过舍入、源一侧按记录值精确。两组都由同一组更高精度的原始值各自舍入时，源的舍入误差乘以 k，会超出目标半个步长，区间求不出交集。

所以本检测器改用对称区间，两侧都按舍入处理，也就不再分方向。

**调用点**：`_audit.py` 的块循环里，在 `detect_relations` 与 `detect_row_relations` 之后。

- `already` 是这两个检测器在本块已经报出的 (方向, 线对) 集合，用于去重。
- 块过宽（`_MAX_BLOCK_COLS`）时不跑列对，与 `detect_relations` 一致；行对照常跑。
- 列方向的发现并入本块的 `relations` 组，行方向的并入 `row_relations` 组。组登记表（`_PRODUCED_BLOCK_GROUPS` / `BLOCK_FINDING_GROUPS`）不变，证据、良性说明、profile 和降权都沿用现有路径。

## 4. 判定

对块内每一对线（行对或列对），分别求比例和差值的区间，扫出极大段，按常数分组。一组同时满足以下各条，才产出 finding。第 3 条的“离开恒等”、第 5、6 条，是原型在曲线族和列对良性家族上逐个排除误报时加入的。每一条都有一条合成测试守着：关掉它，那条测试就会变红。离开恒等、组外偏离、边缘、bits 四处阈值带 1e-9 的相对容差比较（成段比例是整数运算，不需要）：定点小数下这些量会落在格点上——差值臂两侧同步长时，离开恒等和边缘的步数是 0.5 的整数倍，步长不同时是更细的有理格点；组外偏离能恰为 0.05；段内取值范围是步长的 2 的幂倍、且 `n_tests` 是 2 的幂时，bits 能恰为阈值。恰在格点上时，决定过关与否的是浮点舍入，而不是数据。

1. **显著**：分别以两侧当目标打分，取较小值，须 ≥ `PAPERCONAN_LOCAL_RUN_MIN_BITS`。打分按段进行（`_local_group_bits`）：组内每一段的有信息位置，各按本段自己的取值范围用 `_ratio_prediction_bits` 计分，各段相加，最后只减一次搜索惩罚 log2(`n_tests`)。
   - 为什么按段：整组一起打分时，取值范围是全组位置上的范围。排序后的数列、平滑曲线上，零散分布的位置会因此按整条线的范围计分，而每一格其实凭相邻格就能猜到相邻间距那么准；两列各自独立排序的数，就这样被报成了局部段。按段计分，一段的范围是局部的；单独成段的格只用来定常数，不得分。
   - 默认值等于 `_SHORT_ROW_MIN_PREDICTION_BITS`（20），两处口径一致。
   - `n_tests` = 本块该方向的线对数 × 2 种关系 × 线长。
   - 1 位小数、取值分布宽的线，靠格数多过关；高精度的线，短段也能过关。门槛不按小数位一刀切。
2. **局部**：组外偏离的中位数 > `PAPERCONAN_LOCAL_RUN_OUT_DEV`（默认 0.05）。整条线都成立的关系在这里被排除。偏离扣除舍入能解释的部分：
   - **比例**：常数到该格区间的距离 × |a|，再除以这条线 |b| 的中位数。按整条线的量级归一，小数值上的加性噪声不会被放大。原型显示，曲线族的误报都出在曲线最低端那一格。这个中位数不取两侧都读作 0 的格：这种格超过一半时，中位数会变成 0，每格偏离都顶到上限，局部性判据随之失效；
   - **差值**：常数到该格区间的距离 ÷ |c|；
   - 源读作 0、目标不读作 0 的格：用 `_zero_source_miss` 求组的常数离写出它还差多少，除以同一尺度（这条线 |b| 的中位数）；
   - 不提供信息的组外格（两侧都读作 0）不计偏离；
   - 每格的偏离以 `_LOCAL_RUN_DEPARTURE_CAP` 封顶，使中位数有限、可写入 JSON。
3. **常数不平凡**：
   - 比例：区间不含 10 的整数次幂（单位改写，用现有 `_interval_holds_a_power_of_ten`）；1 = 10^0，相同关系因此一并排除，由别处负责；
   - 差值：区间不含 0；
   - **离开恒等**：比例离 1、差值离 0，都至少 `_LOCAL_RUN_MIN_IDENTITY_STEPS`（10）个舍入步长。差值按两侧合并步长算，比例按每格舍入带来的相对宽度算，都取组内中位数。一个缓慢变化的量舍入后，会在一段上“恒定”几个步长，这不是复制造成的。小的差值在比例臂上看起来像接近 1 的比例，所以两臂都要问这一条。
4. **线本身不平凡**：
   - 组内有信息的位置上，A 侧至少有 3 个不同的数：求段时就要求每段如此，每组至少含一段，所以判定时不再查；
   - 行标签匹配 `_AXIS_CONTEXT_LABEL_RE` 的行不参与；
   - 整条线本身是一条刻度的不参与：相邻的有值格之间，一个常数差值或一个常数比例在舍入范围内写得出每一步（`_line_is_grid`）。这包括时间、剂量轴，稀释梯度（比例读法不计 0，梯度末尾常是溶剂对照的 0），以及常数线。线里有重复值时，再按每个值首次出现的顺序读一遍：每个剂量按重复孔各列一次、或整条梯度列两遍，读出来仍是那条梯度。只认精确等差数列时，舍入过的刻度和稀释梯度都会漏过；两列起始浓度不同的 2 倍稀释梯度，一列末尾是 0、另一列多稀释一格，会被报成局部段。
     代价：差值读法也会把在舍入范围内是直线的数据线当作刻度，复制进这种线的一段就不再查找（台架的直线真阳性层记着这个代价）。保留它，是因为两条平行、随后分开的直线趋势在格层面就是“一段平移到另一条线上”；不把直线当刻度，这类良性数据报得更多（台架平行趋势层里噪声远小于一个舍入步长的一档量着这一侧：去掉差值读法时，它由静默变为 partial）；
   - 有限值少于 4 个的线不参与：至少要有一段，外加一个组外位置。
5. **成段**：组内最长的一段至少占组内全部位置的 `_LOCAL_RUN_MIN_CONTIGUOUS_SHARE`（一半），按有信息的格计数：段内两侧都读作 0 的格，以及源读作 0、靠足够大的常数才写出的格，在这个比例里既不拉长这一段，也不计入组内位置。复制一段是连续的；相容位置零散分布在整条线上，是近似整线关系被噪声打碎的样子（例如曲线族里近似成比例的两列）。
6. **边缘突变**：从最长一段的两端向外走，跳过空格（面板分隔行）、不提供信息的格和组内的相容位置，取遇到的第一个组外有值的格。它的偏离扣除舍入后，按该格自身的舍入步长计，须 ≥ `PAPERCONAN_LOCAL_RUN_MIN_EDGE_STEPS`（默认 3）；源读作 0 的格按 `_zero_source_miss` 计。复制的段紧挨着独立数据，边缘是突变的；平滑趋势上的舍入平台、近似整线关系的噪声例外，边缘只偏一两个步长。
7. **去重**：
   - 该线对已在 `already` 中，就跳过；
   - 同一线对两种关系都过关时，只留得分最高的一条；打平时留先找到的：比例臂先于差值臂，同一臂内取最长段种出的组，等长时起点靠前者先；
   - `detect_short_row_reuse` 在全表阶段运行，可能对同一行对再报一次。本设计不做跨阶段去重，重复的情况在评估时计数报告（§8）。

## 5. 输出

两个新的 finding 类型：

- `local_ratio_run`：B = k·A，只在组内成立；
- `local_offset_run`：B = A + c，只在组内成立。

字段如下：

- **线对**：`orientation`（`cols` 或 `rows`）。列对给 `col_a/col_b/col_a_idx/col_b_idx`，行对给 `row_a/row_b/row_a_idx/row_b_idx`。索引沿用现有约定：0-based 的 sheet 绝对位置。
- **关系**：`k`、`k_lo`、`k_hi`（比例），或 `offset`、`offset_lo`、`offset_hi`（差值）；B 是索引较大的那条线。
- **位置**：`segments` 是组内的连续段，每段为 `[起, 止]`，用线上 1-based 的 sheet 行号或列号；`run_length` 是组内位置数；`n` 是其中有信息的格数，即关系真正检验过的格（两侧都读作 0 的格、源读作 0 而被常数写出的格不算），供误报控制读取；`line_length` 是线上两侧都有值的位置数。
- **判据**：`outside_departure`、`prediction_bits`。
- **样本**：`col_a_sample/col_b_sample`（或 `row_*_sample`），沿用 `_sample`。
- **证据**：`example_cells` 列出组内的格，1-based 的 `(行, 列)`，两侧都列。`_attach_evidence` 据此只高亮组内的格，匹配器和 HTML 报告据此定位到单元格。
- **其余**：`severity = "high"`；`rule` 沿用块关系组的命名——列方向 `col[N]`（0 起），行方向 `row[N]`（1 起），例如 `col[5] = col[4] * 1.137 on rows 5-10`——只写常数和段的位置（连续段最多列四个，零散的格只计数）。不写随块范围变化的计数和组外偏离：同一段从重叠的块读出时 `rule` 必须相同，块间去重按 `(kind, rule)` 比较；前置过滤也按 `col[N]` 从 `rule` 里读列号。这两个数都在各自的字段里。

严重度为 high。Task 12 在本地评估集上量过 medium：首屏扰动明显减少、首屏收益几乎不变，但 packet 只收 high，报 medium 时局部发现会全部离开 packet，AI 初筛看不到它们。按这个取舍，由用户决定保持 high（2026-10-18）。

## 6. 良性控制（复用现有规则，不另起一套）

- **按整线对应类型判**：局部段按“关系沿整条线成立时整线检测器会报的类型”来判，`_profiles` 里查表：列方向的比例段对应 `constant_ratio`，差值段对应 `constant_offset`；行方向的比例段对应 `constant_ratio_row`，差值段对应 `offset_row_reuse`（整行没有差值类型，用短行复用检测器的差值类型代替）。
- **派生关系**：`_profiles._is_derived_relation` 按对应类型判。三种对应类型在它的类型集合里，列方向的差值段不在，与整列 `constant_offset` 相同。行方向套用同名行规则：同名行之间的关系不因单位词而豁免。
- **列方向的表头标签分流**：`_profiles._relation_prefilter` 按对应类型判，列方向的两种段分别当作 `constant_ratio`、`constant_offset`；行方向的对应类型不在它认的类型里，不走这一步。派生列、轴、计数、公式或单位换算 → 降权或丢弃，与整列关系同等对待。packet 在 `_distill_relations` 里重算表头分流时也按对应类型判，输出里保留局部段自己的类型名。
- **按对应类型判的已知代价**（Task 8 的审查在合成数据上实测；首屏不受影响，影响的是 severity、packet 和 HTML）：
  - **列方向没有同名保护**：并排面板沿用同一套表头时，同名两列之间的局部段会被降级。两列都叫 `x` 时，表头分流判为 `same_label_replicate`（downweight）；两列都带单位词时（如 `TNF (pg/mL)`），比例段被判为派生，差值段按 `same_label_replicate` 降权。整列 `constant_ratio` / `constant_offset` 本来就这样，`_is_derived_relation` 的同名保护只对行生效。跨面板在同名列上复制一段，正是本检测器要找的形态，所以这是 packet 和 HTML 这一层的召回代价。给列关系一律加同名保护会连带改变整列关系，要单独测量；另一种做法是只对局部段加，不改整列关系，但背离按对应类型判的原则。两种都不在本分支做；Task 12 量这一层的代价。
  - **差值段的分流随方向不对称**：行方向的差值段对应 `offset_row_reuse`。标签带单位词时（如 `IL-6 (pg/mL)` / `TNF (pg/mL)`），`_DERIVED_RE` 把它判为派生而降级，同一对标签在列方向保持 high。两条线同名时反过来：列方向按 `same_label_replicate` 降级，行方向因同名行规则保持 high。按行排列的 dCt/ddCt 表上，行方向的差值段保持 high，因为 qPCR 规则只在列方向的表头分流里。
  - **通用说明挡住更具体的理由**：良性说明在 profile 之前写入 `likely_benign`，而 profile 不覆盖已有的说明，所以局部段在 HTML 里显示的是这句通用说明，不显示表头分流给出的具体理由；`explain` 仍会列出 `prefilter_reason`。整数步长的等差数列也是这样。在共用的写入顺序上改（`_attach_benign` 在前、`_add_context` 不覆盖已有说明）会影响所有类型；只对局部类型改，例如在 profile 之后才补写它们的说明，则不会。留作后续。
- **说明文字**：`_audit.py` 里按类型给出的良性说明，加一句“请核对图注是否说明这一段为换算、归一或共用数据”。
- **文档**：`skills/paperconan/references/detectors.md` 增加两个条目，`output-schema.md` 同步字段。

## 7. 预算与覆盖

- 每块设运算预算 `PAPERCONAN_LOCAL_RUN_BUDGET`。每对线先付一条线长（求段是线性的）；每种关系在分组之前，再为扫出的每一段付一条线长——段数是组数的上界，而每组都要在整条线上走一遍。缓慢漂移的关系可以有很多段，只按线对计数会让预算管不住耗时。付不起时这对线中途放弃，与预算用尽同样登记。分组和逐组判定之前就已付过账，一对线的耗时不会等做完才发现超出预算。代价是按段计费偏松：粗粒度的高表上段远多于组，预算会被高估许多倍，块可能在比完所有线对之前就停下（有登记）。在本地评估集上数这样的块，数量可观再改为按组计费。Task 12 数过：撞上预算的块都是极高极窄的表（列方向，长而粗的线上段极多）或很宽的块（行方向）；评估集里比例、差值类的参考卡目标都不在这些论文里，所以没有挡住评估集上的召回。改为两步分组留作后续，覆盖登记如实保留。
- 预算用尽就停止本块，在 coverage 里登记 `detect_local_pair_runs` / `detector_compute_budget_limit`，与现有检测器同一做法。
- **输出闸门**：新 finding 并入 `relations` / `row_relations` 以后，与其它 finding 一起经过每块的 finding 上限（`_cap_block_findings`）；并入 `relations` 的（列方向）还经过整表的 dense 判定（`_demote_dense_relations`；`_demote_dense_sheets` 只把 `relations` 与 `equal_pairs` 交给它），行方向的块上限是它唯一的按条数计的输出闸门。两处都把两个新类型当作后来者。上限按严重度截断，同一严重度内新类型排在最后：现有 finding 只会被严重度更高的新 finding 挤掉。dense 判定按到来的先后分三类：够得上原下限的关系、短等式、局部发现。每一类只看自己和更早的类加起来的条数，局部发现因此既不能把一张表判成 dense，也不能把短等式挤成 low；表因它们而拥挤时，降为 low 的只有它们自己。不这样做时，Task 7 的审查实测：一个所有列在同一段上互成比例的块，列方向最多可给出 C(n,2) 条局部发现，在审查构造的 20 列块上它们占满了本块上限，把同块其它检测器的 high 发现挤掉；一张整列关系条数恰好等于上限的表，多出一条 `n` 够得上下限的局部发现就被判为 dense，整列关系全部降为 low。全局 finding 预算（`PAPERCONAN_MAX_TOTAL_FINDINGS`）和报告块上限（`PAPERCONAN_MAX_REPORT_BLOCKS`）不分类型：新 finding 会占用后面各块的份额，原本没有 finding 的块有了局部发现，也会占掉一个报告块名额。这两项在本地评估集上量（Task 12）。
- **耗时**：预算按格计，不计每对线的固定开销。审查在合成的高块上量到，新增耗时主要来自行对。在本地评估集上逐篇比本分支与 main 的扫描耗时（Task 12），再决定是否把每对线的固定开销计入预算，或调低行上限。
- 行方向最多比 `PAPERCONAN_LOCAL_RUN_MAX_ROWS`（默认 400）行；更高的块只按列比，并登记 `detect_local_pair_runs` / `detector_row_limit`。实测：不设上限时，高而窄的块（长表）可以生成上百万个行对，把本块的预算和时间都花在行上。`detect_row_relations` 遇到超过 60 行的块整块跳过、不登记；`detect_short_row_reuse` 每张表只比前 400 个候选行，并登记候选池上限。这里跟前者一样整臂跳过，但会登记——只在块里至少有两行能比（至少 4 个有限值）时登记，三列以内的瘦长表行方向本来就比不了，不应被标成 partial。本地评估集参考卡的行对目标都在这个上限以内（Task 12 复核）。列方向不设上限，由预算兜底；但每条线的可用性判断和步长推断在扣预算之前进行，不计入预算，极高的块上这部分开销本身不小，只受 `PAPERCONAN_MAX_CELLS` 封顶。内存上，每条可用线的步长存成 numpy 数组（每格 8 字节），线的副本另占约 8 字节；峰值随块的格数线性增长，同样只受 `PAPERCONAN_MAX_CELLS` 封顶。预算按块计，没有按篇的上限。

## 8. 评估与验收

按 CLAUDE.md 的台架规则：代价按 agent 读到的那一层计；冻结档位，不冻结计数；每条新断言都要确认删掉它守护的代码后会变红。

1. **单元测试**（合成数据，不放任何真实数据）：
   - 区间与段扫描：舍入边界、负源值、零值、方向；
   - 判定各条：去掉任意一条，对应的合成反例必须出现；
   - 去重与输出字段。
2. **台架**：现有的 `tests/test_curve_bench_baseline.py`、`tests/test_column_pair_bench_baseline.py` 只调用各自的检测器，测不到本检测器，它们“不动”是必然的，不能当作验收。所以新建 `tests/test_local_run_bench_baseline.py`：
   - **良性层**：直接导入上述两个台架的生成器，让本检测器在完全相同的良性数据上受检，包括曲线族（逐张表、所有行对）和列对的全部良性家族；另加独立随机数对作远端对照；
   - **独立单调层**：两列各自独立抽取，各自排序（并排的排名表），或各是一条带噪声的平滑曲线。相邻格变化小，常数凭巧合就能对上几格相邻的格；按段计分之前，这一层的多数档会报出；
   - **衰减层**：两条成比例的衰减曲线，尾部接近 0。整条线成立，应由局部性判据挡下；尾部会把这条线 |b| 的中位数（比例臂衡量偏离的尺度）压小。档位如实冻结；尾部近 0 而不恰为 0 时尺度仍会变小，这一点尚未修，先在这一层量着；
   - **稀释梯度层**：两列起始浓度不同的稀释梯度，一列末尾是溶剂对照的 0。整条线成比例，只有最后一格偏离；每个剂量列一次、按重复孔各列一次、整条梯度列两遍三种排法。2 倍稀释靠每条线本身是一条刻度（线的可用性）挡下；3 倍稀释里偏离的那一格偏离不够，局部性闸也会挡下，所以这几档看不到刻度判断的退化；
   - **平行趋势层**：两条直线趋势，先平行、后分开。噪声约在一个舍入步长内的几档如实冻结，是已知代价，不是要压到静默的目标；噪声远小于一个舍入步长的一档，每条线按差值读法是一条刻度，这一档静默，是差值读法换来的收益，与直线真阳性层一起让这项取舍的两侧都在台架上可见；
   - **已知代价层**：“部分换算”，即同一列只有一段由另一列换算而来。数值上与复制一段无法区分，档位如实冻结。表头标签分流能改它的 severity，改不了首屏（§9）；
   - **精度变化层**：整数线中途转为 3 位小数线的布局静默；整数格之间夹一段 3 位小数格的布局会报出，冻结为代价（夹心层，§9）；
   - **真阳性层**：复制一段（4 格、6 格）后缩放或平移，列对和行对都有；另把 6 格复制进独立单调层的一条线里，这是按段计分的代价一侧：排序线、平滑曲线上一段的范围是局部的，复制的一段携带的信息比在无关数值里少；再把一条噪声小于一个舍入步长的直线的 8 格平移到另一条线上，这是把在舍入范围内是直线的线当刻度的代价一侧（只有一部分抽样直到那个程度）。一段覆盖整个植入段才算找到；行真阳性层每层 200 张表，曲线台架的 20 张不够让档位在相邻种子下稳定；
   - 按 CLAUDE.md 冻结档位（静默 / 部分 / 普遍），不冻结计数。报出率压在档位边上的层（SEED 与 CV.SEED 一起移动时实测翻过档的）冻结为它跨着的两档之一，掉出这两档仍然失败；
   - 台架能看见哪些判据、看不见哪些，在台架文件的 TEETH 一节如实记着。边缘、连续性、离开恒等、不同源值数和 10 的整数次幂这几道闸放松到 TEETH 所列的值时台架不动，放松它们只有单元测试守，不能拿这个台架论证；收紧离开恒等时夹心层变静默，§9 给精度变化高估提的修法可以在夹心层上量；同时会有真阳性层变静默，代价也在台架上看得到。
3. **本地评估集**（不入库）：
   - 发 v2 命中范围：只在比例、差值两个家族里加入两个新类型，目标卡不动；v1、v2 都报数；
   - **收益**：`compare_runs.py` 对比当前 main 的扫描，按卡看检测层和首屏两层的升降；
   - **代价**：同一脚本统计每篇论文首屏新进和被挤出的 panel，按类型和逐篇分布报；新进和挤出两个方向都要报。
4. **全套测试与 golden** 保持通过；合并前过独立子代理审查。

**合并的门槛**：

- 两个台架的良性层不动；
- 本地评估集首屏上的收益大于挤出；
- 审查没有未处理的阻断项。

三条都满足才合并。

## 9. 风险

- **部分换算的良性列**：同一列里只有一段是计算出来的，比如只对子面板归一。它在形态上就是局部段。列方向的表头标签分流（§6）改的是 severity、packet 和 HTML，改不了首屏：首屏按 `raw_severity` 排，那是分流之前的值。所以这类良性段在首屏上的代价只能按 §8 第 3 条去量。表头分流之后还能调的是新类型的初始严重度；收紧检测器的判据，或在发出 finding 时就按表头处理（在 `raw_severity` 定下之前），同样能改变首屏。行方向的部分换算台架量不到：归一化通常是除以一个对照（k < 1），行真阳性层植入的 k 在 1.15 到 2.4 之间，Task 9 的审查把 k 换成除以对照后，四个层里有两个档位不同，所以不能拿行真阳性层代替。这是记录在案的缺口，不另建一层（会再加运行时间）；行方向不走表头分流，派生规则只看行标签（§6），首屏上的代价在 Task 12 量。
- **数量级盲区**：带尾零的大整数按步长 1 读，按有效数字舍入复制的段对不上，真对上时打分也按步长 1 算；按 10 位小数的读出精度，绝对值低于 5e-11 的值读作 0，这样的线所有格都不提供信息；再大一些但只剩一两位有效数字的值（例如 1e-9 量级），区间很宽，段也难对上。记为缺口，`detectors.md` 的“不报的情形”写着。
- **记录步长推断**：`_effective_line_quantums` 仍可能把个别带公式缓存值的格读得过细。区间过窄只会让匹配变严；打分时，`_ratio_prediction_bits` 的 `max_quantum_ratio` 上限限制单格贡献，用单元测试锁住这个上限对新检测器同样生效。固定有效数字与固定小数位两种模式都解释不好的线（混合导出），按固定小数位处理，与现有行为一致。
- **对称区间更宽**：两侧都按舍入处理，比单侧区间宽，更容易连成段。由显著性门槛和局部性判据把关，代价在新台架上量。
- **平滑或直线数据上的巧合段**：两条先平行、后分开的直线趋势，以及尾部接近 0 的成比例衰减，在检测器层仍会报出一部分（台架的平行趋势层冻结为 partial；衰减层冻结为 silent，即报出的抽样不超过 5%）。按段计分只按段内的取值范围计信息，没有扣除一格凭相邻格就能猜到的那部分。先在本地评估集上按 agent 读到的首屏量（§8 第 3 条），再决定是否改打分。
- **精度沿线变化的线**：几个粗格定出一个宽的组区间，只与它相交的细格按自身的步长计分，离开恒等也按细格的半宽算。我们构造的一种布局（整数格之间夹一段 3 位小数格，差值随意落在区间里）会报出，台架的夹心层把它冻结为代价；较真实的布局（整数行之后接 3 位小数行）台架记为静默；未在语料上量过。修法方向是：细格的计分步长和离开恒等的半宽，下限取常数实际能分辨的宽度。先测量再采用。
- **首屏挤出**：新的 high 级 finding 会和现有 panel 争首屏。按 §8 第 3 条量，代价过高就降为 medium，再量一次。Task 7 的审查在合成数据上做过一次测量（不是台架）：按批次对照归一的百分比、按板校准的 ddCt、各组 n 不同的 SEM = SD/√n，这三种按构造良性的形态都报成 high，三种都改变了首屏上的内容：SEM 那例的位置多出一个 family，high 数由 1 变 2；百分比那例多出一个位置（该文件原本没有）；ddCt 那例的位置由 medium 升为 high。每个合成文件只有一个位置，没有测到名次变化；三种改变的都是排序所用的键。表头分流移不动它们（见上文“部分换算的良性列”）。
- **评估集上首屏代价的构成**（Task 12，逐条读数据归类；本地记录）：§9 前面记下的几种形态（先平行后分开的直线、精度沿线变化、尾部近 0 的衰减）在首屏上很少。不在参考卡目标上的首屏位置，大多数是已有位置多了一个局部段的 family。良性的大头是**格点/粗精度**：整条线的值都是某个公共步长的整数倍（小计数的分数或百分比、整数乘因子、落在 0.01 Ct 格点上的 2^-ΔΔCt），检测器却按打印出来的位数计信息，格点上几步的吻合被算成很多 bits。其次是**统计输出表**（t = 差值 / SE、Mean diff = Mean1 − Mean2，SE 或参照列为常数），以及**跨不同量纲列的行**（整数索引或计数格在舍入范围内配得上任意常数）。修法方向记为后续：按线的格点步长计分；统计输出表用结构判据（块内一列为常数）；行方向只计区间紧的格。另有一部分是参考卡之外、值得人工复核的待解释信号，未经盲测复核，不作结论。
- **耗时**：Task 12 在较重的论文上比过同一机器下 main 与本分支的 CPU 时间，本分支更慢，增量集中在少数几篇；修法方向是把每对线的固定开销计入预算，或调低行上限，留作后续，取舍前先量行方向参考卡目标所在块的高度。
- **证据窗口可能只落在段内**：`example_cells` 只列组内位置，证据窗口以这些高亮格为中心截取。块比窗口小时整块存下；段的高亮跨度达到窗口上限（列方向 `PAPERCONAN_MAX_EVIDENCE_ROWS` 行，行方向 `PAPERCONAN_MAX_EVIDENCE_COLS` 列）时，存下的窗口只落在段内，看不到这一段在哪里断开，要用 `explain --full`。比上限至少短两格的段，两端在块内的断点都在窗口里，只是段外的格不高亮；只短一格时，窗口居中取整，一端的断点可能落在窗口外。可以把每段两端外第一个有值的格也列进高亮，留作后续。
